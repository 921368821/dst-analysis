# 深度注释标准作业规程（SOP）

> 派子代理做深度注释时**必须**附上本文。历史上出现过子代理提前返回、
> 产出不完整、被覆盖等问题。

## 背景

DST（饥荒联机版）拆解工程。目标：给 Lua 源码加逐行深度中文注释，
供用户移植引擎 + 自研游戏参考。

**绝对红线**：注释版**只能增加注释**，可执行代码必须与原版逐字节一致。
任何改动都要能通过 `tools/verify-annotated.mjs` 校验。

## 数据流

```
原始源码（只读，永不修改）—— 路径**不再写死**，由 tools/lib/paths.mjs 解析：
  ① $DST_PRISTINE / $DST_SRC   ② <工程根>/_baseline/pristine-scripts
  ③ <工程根>/dstsrc-pristine/scripts        （三条都不成立 ⇒ 直接报错，不许退回注释版）
        │
        │ build-<name>.mjs 逐行读出，代码行原样输出
        │ 注释从 spec-<name>.mjs 注入：旧写法按「行号」，新写法按「定义名#第 n 次出现」
        ▼
注释版输出（= <工程根>/02-注释源码/scripts/<相对路径>，同样不写死）
```

> ★ 2026-10-19（M8）之前，源/输出两边都是**写死的绝对路径**，而且分散在 104 个
> `build-*.mjs` 里各抄一份。工作区搬过一次家，于是 104 个脚本**同时**指向不存在的目录，
> 报出来的还是 `ENOENT ... 35916 ...`（别人的机器）。
> 现在统一走 `tools/lib/paths.mjs`，可用
> `node tools/relocate-paths.mjs --check` 一条命令复查（必须 0 个）。

## 标准流程（6 步，一步都不能省）

### 1. 先看结构（不要凭文件名猜内容）
```bash
grep -nE "^(local )?function |^function [A-Z]" "<源文件绝对路径>"
wc -l "<源文件绝对路径>"     # ★ 必须先确认真实行数，后面 spec 的行号都依赖它
```

### 2. 真的读源码
用 Read 工具读**最关键的 3–5 个函数**的实现（不是只看签名）。
注释质量完全取决于这一步有没有真的读懂逻辑。

### 3. 写 spec 文件 `<工程根>/tools/spec-<name>.mjs`
```js
// 键的两种写法（M8 起推荐锚点）：
//   134                —— 旧：源文件第 134 行之前（原版一插行就错位，仅存量使用）
//   "Brain:OnUpdate#1" —— 新：`Brain:OnUpdate` 的**第 1 个定义**那一行之前
//   "Brain:OnUpdate#1+7" —— 新：定义行往下第 7 行之前（函数体内的具体语句）
// 值 = 注释数组，每项必须以 -- 开头（空字符串表示空行）
export default {
  1: [
    '--[[',
    '-- <文件名> —— <一句话职责>',
    '--',
    '-- 【最重要的三件事】',
    '-- 1) ...',
    '-- 【⚠️ 容易踩的坑】',
    '-- ...',
    '--]]',
  ],
  // ...
};
```
**规范**：
- 只给**真正值得解释**的行加注释（函数定义、关键分支、魔法数字、复杂公式）
- 不要逐行翻译代码——那是噪音
- 用 `★` 标重点、`⚠️` 标陷阱、`【】` 标机制
- 发现真实缺陷必须**在注释里写清行号依据**，且**你本人已对照源码核实过**
- 新写 spec **一律用锚点键**；数字键只在「第 1 个定义之前」这类文件头区域才允许
  （那里没有函数名可用）。锚点找不到会**直接抛错**，不会静默跳过。

### 4. 写 build 文件 `<工程根>/tools/build-<name>.mjs`
直接复制 `<工程根>/tools/build-combat.mjs` 并改这四处：
- `SRC` = **`relSrc("<相对 scripts 根的路径>")`**（不要写绝对路径；见 tools/lib/paths.mjs）
- `SPEC` = 对应 spec 路径（`join(__dirname, "spec-<name>.mjs")` 即可）
- `OUT` = **`relOut("<相对 scripts 根的路径>")`**
- `HEADER` 数组（第 24–47 行）—— ⚠️ **必须整体重写**，不要留上一个文件的描述

保留文件末尾的两条断言函数 `assertComment`（校验 `--` 前缀 + U+FFFD）。

### 5. 构建并校验（四道关卡，全过才算完成）
```bash
# 关卡1：spec 体检（批量，一次列出全部问题，避免反复往返）
node <工程根>/tools/lint-spec.mjs spec-<name>.mjs

# 关卡 2：构建
node <工程根>/tools/build-<name>.mjs

# 关卡 3：★ 全局校验器（必须看到「全部通过」）
node "<工程根>/tools/verify-annotated.mjs" \
  "$DST_PRISTINE" \                      # 原版根；没归档过就先跑 tools/archive-pristine.sh
  "<工程根>/02-注释源码/scripts"
# ⚠️ 退出码是三分语义，**不要只看「有没有报错」**：
#   0 = 逐字节一致 / 1 = 有差异 / 2 = **无法复验**（例如原版缺失、或两边是同一棵树）
#   ★ 曾经把 `<工程根>/dstsrc/scripts` 当原版传进去 —— 那是注释版的联接，
#     等于「自己比自己」，永远 0；现在这种情形会直接返回 2 并说明原因。

# 关卡 4：★ 全量语法体检（★ 唯一能抓出「注释引入语法错误」的工具）
"$PY" "<工程根>/tools/verify-syntax.py" --quiet
# 必须看到「★ 真缺陷: 0」；若打印「⊘ 无法判定」（退出码 3），
# 说明没找到原版根 —— 那不是通过，是没测。
```
⚠️ lupa 是 Lua 5.5，**`loadstring` 已移除**，必须用 `load(src, name)`。

### ★ 为什么关卡 3 和关卡 4 都不可省

`verify-annotated.mjs` 只比对**可执行代码行**，因此
**查不出注释引入的语法错误**。实测真实案例：
`spec-inventory-p9.mjs` 的注释里写了「（[[ ]] 形式）」，
其中裸 `]]` 提前闭合了源码的 `--[[` 长注释块，
让下一行 `CloseControllerInventory()` 裸露成代码 → 语法错误，
而关卡 3 依然显示「全部通过」。

`verify-syntax.py` 会自动跑一遍原版做对照，把
Lua 5.5 严格性导致的问题标为「基线」（当前 11 个，不是我们的错），
只有「仅注释版失败」才报为真缺陷。

### 6. 更新索引 `<工程根>/02-注释源码/注释源码总索引.md`
在深度注释表格里加一行，并更新表头的文件数与总行数。

## 锚点迁移（M8，2026-10-19）

存量 spec 仍是**行号键**，一共 **23486 个**（258 个 spec 文件；`--status` 可随时查）。
`node tools/spec-keys.mjs --all --status` 就是进度表 —— 数字会自己说话。

迁移命令（**前置：先归档原版源码**，否则算不出锚点，工具会返回 2「无法判定」）：

```bash
bash tools/archive-pristine.sh <原版 scripts 根>
node tools/spec-keys.mjs --all            # 演练：只报数，不写回
node tools/spec-keys.mjs --all --write    # 写回
node tools/spec-keys.mjs --all --status   # 复查：数字键应为 0
```

迁移的安全网（`node tools/spec-keys.mjs --selftest` 逐条验，且都能红）：
- **P1** 同一份源码 ⇒ 迁移前后**注入产物逐字节相同**（不然就是改了内容，直接拒绝）
- **P2** 上游插入 2 行后：数字键错位、锚点键仍精确落在原函数之前
- **P3** 找不到定义 / 第 n 次不存在 / 偏移越界 ⇒ **抛错**，不静默跳过

## 常见坑（都是实际踩过的）

1. **行号错位**：凭印象写行号 → 必翻车。写之前先 `wc -l` 和 `sed -n 'Np'`
   核对。spec 里若有越界行号，build 会直接报错（这是保护，不要绕过）。
   新 spec 请直接用锚点键（见 §3），从根上避掉这一类。

2. **注释行漏 `--` 前缀** → 断言会拦下。不要因为"看起来像注释"就跳过

3. **中文编码损坏（U+FFFD）**：spec 写入时个别字符被截断，
   **肉眼几乎看不出来**。`assertComment` 能抓到输出里的，
   但**抓不到 spec 文件自身 JS 注释行里的**（那些不参与注入）。
   → 构建前先单独扫一遍：`grep -c $'\ufffd' spec-<name>.mjs`

4. **注释掉的代码 ≠ 未实现**：
   例如 `container_replica.lua` 的 `OnRemoveFromEntity` 是被注释掉的
   （源码注明 not supported），实际生效的是 `OnRemoveEntity`
   且带 `if TheWorld.ismastersim` 只在服务端跑。
   → 写注释前确认钩子是否真的启用、跑在哪个端

5. **★ 写完 spec 先 `node --check` 语法** ⚠️ 新增，已实际卡住两次
   spec 是 JS 文件，语法错误（逗号结尾、缺括号）报的错是
   `Invalid or unexpected token`，很难定位到具体行。
   → `node --check spec-<name>.mjs` 一步到位，**在构建之前**跑。

6. **⚠️ 别凭印象给子代理报文件路径/行数** ⚠️ 反复踩到
   本轮我给子代理的候选文件里，`ghosthouse.lua` / `attacks.lua` /
   `pointything.lua` / `useable.lua` **全部不存在**；
   `behaviours/` 目录我给的行数有 3 个少 7 行（末尾无换行符）。
   → 派任务前自己 `ls` + `wc -l` 核实一遍。
   → 好的一面：子代理会如实纠正（4 个代理全部纠正了我的错误），这种任务书
     允许写"如果你发现描述不符请纠正"，能换回高质量的诚实反馈。

7. **不要用 sed 派生 build 脚本**：HEADER 里的职责描述不会被替换，
   会把上一个文件的描述带过去。要复制后手工改 HEADER

6. **★ 注释正文里的 `--[[` 或 `]]` 字面量会提前闭合块注释** ⚠️ 已实际踩到
   Lua 源码里常有 `--[[ ... ]]` 长注释块。若你的**注释文字里**出现这两个序列
   （比如解释「这里用了块注释」），会提前闭合源文件已开启的块 → **语法错误**。
   而且全局校验器**查不出来**（它只比对代码行，不做语法编译）。
   - 规避：写成 `--[ [` / `] ]`（中间加空格），或直接说「长注释块」
   - **只有第 5 步的 Lua 语法检查能抓到**，所以那道关不能省
   - `build-templates.mjs` / `build-inventorybar.mjs` 已加守卫

7. **★ 注释里不要出现 `\r` 转义** ⚠️ 已实际踩到
   若注释正文写了 `/\r?\n/` 这类正则字面量，工具链可能把 `\r` 当成真回车，
   把一行劈成两行 → 语法错误。同样只有语法检查能抓到。
   规避：改用不含反斜杠的措辞（「兼容 CRLF 与 LF」）。

8. **★ 动手前先 `ls` 确认工具文件名没被占用**
   `build-map.mjs` 早已被 map/ 目录的批量构建器占用（103KB，引用 20 个 spec），
   乱覆盖会毁掉别人的工作。命名带上目录前缀，如 `build-components-map.mjs`。

9. **不可信的"完成"汇报**：交回前自己跑一遍三道关卡，
   并 `ls -la` 确认输出文件真的落盘、行数合理。
   **主代理必须独立核实每个数字**——历史上子代理谎报/半成品是常态。

10. **行数口径**：`wc -l` 在文件末尾无换行符时会少算 1。
    要精确行数用 `awk 'END{print NR}'`。
    另注意 build 脚本打印的「输出行数」是多行字符串按**一个元素**计，
    与 `wc -l` 的物理行数差一个 HEADER 的行数，属正常。

## 注释内容要求（区别于"翻译代码"）

好的注释回答的是「**为什么这样写**」和「**换个写法会怎样错**」，例如：
- `damage = basedamage * mult1 * mult2 ... + bonus` →
  说明八项正交修正器结构、为什么 bonus 单独走加法、为什么各项要 `(x or 1)` 兜底
- `DoPeriodicTask(1, fn)` →
  说明回调是协程、可 yield、会导致周期漂移，引用 bug-patterns A1
- `if TheWorld.ismastersim then` →
  说明这决定代码跑在服务端还是客户端，直接影响能否信任它对 UI 的影响

差的注释是：`-- 这里是循环` `-- 设置 x 为 1`（纯翻译，删掉不影响理解）
