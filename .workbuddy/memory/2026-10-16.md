### 拾取接通（§9w.2 第 2 条的正解）

旧诊断「`inventory:GetItems()` 不存在（宿主是桩）」**是错的**：
原版 `Inventory` **根本没有 `GetItems`**（真接口 `GetItemInSlot`/`FindItem`/`Has`/`GetNumSlots`/`GiveItem`），

真正缺的是两处 **07 侧接线**：
1. `action_for()` 只认 workable/pickable/harvestable ⇒ 地上的**物品**不算目标（已加 `inventoryitem`）；

   对带 target 的动作走 `GoToEntity`，**动作是在「到达」之后才执行的**，而算出的到达距离 ≈0
   （实测只有站在物品**正上方**才算到达）⇒ push 成功却静默无反应。
   用原版**自己留的钩子** `bufferedaction.arrivedist` 补上（与 ACT_HIT 同值），
   并且**只在 `distance` 与 `arrivedist` 都缺时才补**、还要**记账**（`act_arrive_patched`，进 stats）。
   ⇒ 判据 E3：物品进背包 + 离开世界；反向：没被 act 的那份一动不动；补参数**必须有记账**。

## 2026-10-16 第 43 轮：P26 死亡 ⇒ 自动复活（消掉「世界永久停摆」）

| 位置 | 做法 |
|---|---|
| `rt_boot` | `M.respawn(slot)`：**移除尸体 + `add_player` 生成新身体**（复用已过测的槽位生成路径）；没死就拒绝并说原因。`auto_respawn()` 每拍检查，死满 90 拍（3 s）自动复活 |

★ 用「**拉取自愈**」而不是「服务端推送换人」：本工程量过推送在负载下十几秒发不出去，
`you` 握手当初正是因此改成拉取的。

## 2026-10-16 第 54 轮：P36 收尾 —— D4 第二次红，是**判据自己的包装**吞了返回值

P36（会话身份挺过重启）的实现三处（`rt_save` / `rt_boot` / `server.py`）都已落地，

```

```

`p0`（**存档前**位置）是 `None`、`p1`（读档后）正常 ⇒ 一眼是**读自己**的毛病。根因：

```python
def ev(code):  return L.eval("(function() " + code + " end)()")     # 包一层 IIFE
def pos_of(guid):  return ev("""(function() … end)()""")            # ← code 自己已是 IIFE
```

外层函数体里只剩一句**表达式语句、没有 `return`** ⇒ 外层返回 `nil` ⇒ Python 拿到 `None`。
`p1` 走的是裸 `L2.eval(...)`（没经 `ev`）所以正常 —— **两处实现不一致**才让它显形。

★★ 这正是本工程的老母题「**判据错被当成宿主缺口**」的第 N 次复现：红灯看着像引擎没保住
  位置，其实是**判据自己**的包装吞掉了返回值。⇒ 已把 `pos_of` 改成直接 `L.eval`，
  并把两处读法统一成**同一个**脚本函数（一处实现，防再漂移）；注释里写死
  「`ev()` 只包**片段**（如 `RT.set_slot_keys{…} return true`），**不要**包自身完整的 IIFE」。

**修完做了变异测试**（「检查写好了 ≠ 检查生效过」）：把 `rt_boot` 里
`local restored = meta.restored or {}` 临时改成 `local restored = {}`（= 不翻译 旧guid→新实体），
`D4` 立刻红在「读档后槽位没绑回来：`{0: 40}`」⇒ 确认这条判据**真的**在守护那段重绑定逻辑。已还原。
