### 二、P39：血 / 饿 / 理智 / 背包看得见

链路：`M.player_state(slot)` → 模拟线程每 8 拍算好 `hub.me_by_slot` → WS `{"cmd":"me"}` →
客户端 `meLine(st)` 上 HUD。与 `targets` **同一种模式**（拉取，不推送）。

**这一轮踩到的三个坑，都值得记**：

① **隔离手段把被测的量一起钉死了**：判据要证明「饥饿真的在掉」，而为防玩家死掉用了
`_pin_player_alive`（`health:SetInvincible(true)`）⇒ 原版 `hunger.lua` 的
`DoDelta(delta, overtime, ignore_invincible)` 里 `health:IsInvincible()` 会**早退** ⇒
**无敌的玩家饿也饿不着**，实测 `150.000 → 150.000`，看着像「饥饿是死值」。
⇒ 改成**逐拍补血**（`currenthealth < maxhealth` 时 `SetPercent(1)`），立刻变成 `150 → 149.6875`。

② **按槽位缓存的数据会活得比它的主人长**（**真缺陷**，不是判据错）：
`E10` 单跑绿、整轮跑红（`me` 回 `ok=true`，而 `/healthz` 的 `stats.players` 里没有那个槽位）。
真因：`me_by_slot` 按**槽位**存，而槽位会**换主人**（旧角色被回收、槽位分给新连接），
下一轮刷新（≤0.27 s）之前缓存里是**上一个角色**的血/饿/背包。
⇒ 两道修：`alloc_slot` 换主人时作废 `me_by_slot`/`targets_by_slot`/`act_result`；
出口再按 `guid` 与 `slot_guid` 对账，对不上就说「还没算出来」。
**形态**：有字段 ≠ 那个字段说的是你。

③ **一份 JSON 里两个叫 `players` 的东西**：`/healthz` 顶层是**在线人数（int）**，
`stats.players` 是**按槽位的表（dict）**。顶层那个既没文档也没消费方，我按直觉写
`h["players"][str(slot)]` ⇒ `'int' object has no attribute 'get'`。⇒ 顶层改名 `player_count`。
