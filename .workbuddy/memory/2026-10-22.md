# 08-引擎内核 · 工作日志

## 2026-10-22 第三轮：16 位真的进 GPU · APNG 有了时间轴 · JPEG 自写 DCT

**起点**：上一轮把 PNG 的三块"明确不支持"（Adam7 / APNG / 16 位）变成了"有判据的已支持"，
但三处仍是**半截**：

| 问题 | 症状 |
|---|---|
| 16 位进 GPU | `TextureDesc` 只有 `rgba8`，解码器只能降采样 —— "支持 16 位"止步于内存 |
| APNG 播放时间轴 | 只有帧列表，没有"什么时候显示哪帧"；若把计时器放图集，同一素材在两个世界会互相干扰 |
| JPEG | 明确不支持。一个需要用 JPEG 的项目在这个内核上根本立不起来 |

判据 317 → **427**，变异 13 → **18 组**（新增 5 组全在 JPEG）。

### 一、三块的落地顺序都是"先定契约，再写实现"

- **16 位**：`PixelFormat.RGBA16` + `bytesPerPixel()`（格式→字节数**只此一处**。
  本仓库有过"同一原语两层各写一份、B 通道 basis 漂移"的事故，凡是映射表一律单点）。
  图集 `precision: auto/8/16`，`pixels` 恒存在（8 位视图）且 `pixels[i]===round(pixels16[i]/257)`，
  这条不变量是**构造性质**（16 位路径的 8 位视图由 pixels16 派生），不是靠测试去发现漂移。
- **时间轴**：`AnimationClip` 冻结只读 + `sampleClip` 纯函数 + 组件持 `timeMs`。
  **图集不持计时器**是唯一硬约束（同一素材在两个世界播放必须互不干扰）。
- **JPEG**：自写 DCT。加这一块的判断标准不是"写多少行"，而是"怎么写判据"。

### 二、三个真实缺陷（都由验证抓到）

1. **webgl2 的 `glFormat` 把 RGBA16F / 未知格式静默落到 RGBA8**（既有缺陷）。
   `texImage2D` 的 type 还硬编码 `UNSIGNED_BYTE`。⇒ 显式 case + `default: throw`，
   type 取自格式三元组。**"静默回落"是这类映射表最危险的失败模式**：调用全成功、画面错。
2. **`gfx-null` 只对 render target 校验 4 字节/像素**，普通纹理不校验 ⇒ 传错 bpp 不会被发现。
   ⇒ 全格式按 `bytesPerPixel` 校验，不符报 `GFX.SIZE_MISMATCH`。
3. **渐进式 JPEG 的 AC 精修 EOBRUN 少算当前块**：`(1<<r)-1+receive(r)` 在 `r=0` 时得 0，
   本块剩余非零系数的修正位一个都没读，位流从此错位（灰度渐进图单通道差 28）。
   ⇒ 改成"包含当前块"的 `(1<<r)+receive(r)`、块尾统一减一，同一张图降到差 1。

> 定位这条错误的路径值得复用：**一次只放开一个变量**。
> 按扫描截断生成 Pillow 中间态金标 → 逐扫描比对定位到 AC 精修 →
> 导出系数做前向 DCT 逐系数比 → 最后用灰度图把"色度上采样"彻底排除。
> 三个变量一起看只会看到"花了"。

### 三、两个"看起来能测、其实测不准"的坑

**(a) 用"补了多少个 0 位"判断 JPEG 截断 —— 方向都错。**
位读取器会**预读**（缓冲填到 >24 位），所以补位数 ≠ 缺失位数：完整的 `restart-prog-420`
因 24 个重启区间各在末尾多读十几位而补 470 位，而截到 90% 的文件只补 246 位。
⇒ 换成**结构性事实**：熵数据是否以 EOI 收尾。完整文件恒 true，截断恒 false，不依赖任何阈值。
教训：**能用结构判定的，不要用统计量判定。**

**(b) 变异点会随实现漂移而失效，而"没找到变异点"会被误读成"判据假绿"。**
`M6`（图集像素没传给 GPU）原来匹配 `atlas.pixels,` 单行；16 位改造后上传目标变成
`upload`（8/16 位按格式选），变异器报"变异点没找到"。
⇒ 变异组的匹配串是**实现的一部分**，改实现就要回头看变异是否还咬得住。

### 四、JPEG 判据的形态（可复用到任何有损格式）

| 层 | 做法 |
|---|---|
| 语料 | `tools/make-jpeg-fixtures.py`：Pillow 编 14 例（三种过程 × 三种采样 × 灰度/CMYK/EXIF/退化尺寸） |
| 金标 | 同一批文件用 Pillow(libjpeg-turbo) 解成 `.rgba`，`maxAbs/meanAbs/sha256` 写进 manifest |
| 阈值 | **来自实测**（4:4:4 → `(3,0.15)`，4:2:0 → `(4,0.5)`～`(6,0.5)`） |
| 自检 | 把金标整体 +（`maxAbs`+1），同一比较器**必须判失败** —— 否则 `maxAbs` 改成 255 也全绿 |
| 不变量 | 同源四种编码（基线/渐进/重启/渐进+重启）解出**逐字节相同**；灰度 R=G=B；EXIF apply == 金标旋转 90° |
| 消费 | `textureImporter`(.jpg) → `decodeImage`（按魔数）→ 图集合成 → `createTexture`；`web/assets/photo.jpg` 是真的在用 |
