## 一、并行性判定（先判后做，不猜）

| 维度 | 线 A 脚本层 | 线 B 资产导入 | 是否冲突 |
|---|---|---|---|
| 功能依赖 | 需要 L1 脚本接口 + 平台接线 | 需要 `IFileSystem` + `AssetDatabase`（都已有） | **无** |
| 新增代码目录 | `backends/script-lua`、`extensions/script` | `extensions/asset-import` | **不重叠** |
| 新增判据目录 | `tests/contract`、`tests/backends`、`tests/core/script-*` | `tests/extensions` | **不重叠** |
| 需要改的既有文件 | 无（接口由地基提供） | 无（`core/asset` 不动） | **无** |
| 语义耦合 | 脚本可以读资产，但**不必须** | 导入器不需要脚本 | **无** |

**结论：可并行。**

但"可以并行"不等于"直接开两个 worker"：两条线都要在
`platform/registry.ts`、`platform/platform.ts`、`core/tokens.ts`、`runtime/GameApp.ts`、
`backends/index.ts`、`tests/run.ts` 上各加几行 —— 这两组改动**必然打架**。

所以执行形态是 **"地基串行 → 双线并行 → 集成交叉"**：

```
① 地基（串行，主线程，一次性）
   L1 脚本接口 · registry.kind · IPlatform.script · Services.Script · GameApp 接线
   · backends/index 导出 · tests/run.ts 改自动发现（消除后续所有登记冲突）
   ↓ 冻结
② 双线并行（文件白名单互斥，见下）
   ├─ 线 A：script-lua + 脚本契约 + ScriptModule + 端到端
   └─ 线 B：.meta + importer + pipeline + 判据
   ↓
③ 集成（主线程）
   宿主接线（web/headless）· ARCHITECTURE · 全量判据 · 变异验证 · 提交
```

> `tests/run.ts` 改成目录自动发现，是这次并行化的**前置条件**：
> 原先是显式 import 清单，两条线同时新增判据就必然改同一个文件。

## 四、本轮修掉的真问题（全部由判据/变异验证发现）

| # | 问题 | 症状 | 根因 |
|---|---|---|---|
| 1 | **节点 id 是进程级全局自增** | 两个独立实例跑同一脚本，存档只差 id ⇒ "逐字节相同"失败 | `NEXT_NODE_ID` 在模块级；`Scene` 没有自己的 id 空间。改为 `Scene.allocateId()`（每个世界从 2 起） |
| 2 | 脚本每 tick 的调用可能乱序 | 慢脚本时两个 tick 交替改同一全局变量 ⇒ 抖动 + 存档不可复现 | 宿主在同步 `onStep` 里驱动异步 `call`；补串行队列（上限 4，满了丢弃并计数） |
| 3 | 同步 pump 的宿主会把脚本队列打满 | `for` 循环跑 300 帧，脚本只执行 4 次 | 队列上限是对的，但缺少"排空"原语 ⇒ 补 `drain()` |
| 4 | 导入管线"全绿但资产进不了世界" | `db.load()` 永远 `ASSET.NO_LOADER` | 有导入没有加载器（中间层做完两头没接）⇒ 补 `loaders.ts` |
| 5 | 删除源文件留下幽灵注册 | `describe()` 里永远有它、`dependents` 还把它算进依赖 | `AssetDatabase` 没有反注册 ⇒ 补 `unregister` + 清洗（`removed` 计数） |
| 6 | wasmoon 在 Node 22 下初始化失败 | `Aborted(Assertion failed)` in `environ_get` | emscripten 断言环境变量 `charCode ≤ 255`，而 `_`（程序名）= 含中文的测试路径 ⇒ 显式 `environmentVariables` 覆盖 + 临时净化 |
| 7 | `instantiateStreaming` 会先失败一次 | 控制台警告"falling back to ArrayBuffer" | 静态服务器没给 `.wasm` 正确的 MIME ⇒ 补 `application/wasm` |
| 8 | 变异验证的第一版是**等价变异** | M1 改 `throw` 后判据没红，看着像"判据假绿" | `throw` 被同一 for 里的 `catch` 接住，行为几乎不变 ⇒ 改成 `return`（中断整帧）才真正破坏隔离 |

## 五、本轮**没做**（诚实清单，对应 ARCHITECTURE §11.2）

- **Lua 5.1 兼容层**：wasmoon 是 5.4，DST 内容层是 5.1（`setfenv` / `module()` / `unpack`）。
  没有它就无法真正跑 153 万行 —— 这是下一阶段的第一优先级。
- **headless ↔ 浏览器逐字节存档**：浏览器侧只断言到"Lua 算得对 + 跨边界日志可见"（4 条），
  逐字节比对需要手工导出存档。**这条出口判据不算达成**。
- 脚本模块的 per-module `_ENV` 隔离（现在只隔离了函数名，全局变量共享 `_G`）。
- 像素解码（PNG inflate）/ GPU 上传；`fs-node`；按类型的导入设置；编辑器；构建发布。
- 浏览器端的**自动化**验证：本机没有可用的浏览器自动化能力，`selftest.html` 需人工打开确认。

## 八、范围边界（诚实标注，不假装完成）

- **Lua 版本**：wasmoon 是 **Lua 5.4**，DST 内容层是 **5.1**（`setfenv` / `module()` / `unpack`）。
  本次打通"接口 + 执行 + 隔离"，**不做 5.1 兼容层**；迁移 153 万行的四类差异已记录在
  `docs/ARCHITECTURE.md §12`。
- **贴图解码**：texture importer 只解析 PNG **头**（宽/高/位深/色彩类型），交付元数据 + 原始字节；
  真正解码像素（zlib inflate）需要平台能力，留给 `gfx` 加载器（浏览器 `createImageBitmap`）。
  这不是偷懒：在 L4 里手写 inflate 会在浏览器与 Node 各写一遍，且看不见收益。
- **不做**：编辑器、构建发布、AI、世界生成（阶段 3–5）。
