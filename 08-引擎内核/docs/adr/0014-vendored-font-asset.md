# ADR-0014 · 第三方字体资产：只取原生 BDF 的 OFL 字体，只打声明的字符集

- **状态**：已采纳（`tests/extensions/ui-cjk-font.test.ts` 15 条 + `tests/host/hud-ui.test.ts`
  的中文接线 2 条 + `tests/extensions/editor-asset-bake.test.ts` 的 `isUiPage` 1 条强制；
  变异 M523–M535 证明判据不空转）
- **日期**：2026-10-27
- **背景**：阻塞清单 C8。C9 落地之后 UI 该有的能力都在了，唯独中文文案进不去 ——
  `toast`、`ITEM_LABEL` 一直留在 DOM，HUD/背包只能用 `kind` 的英文形式。
  卡点不是代码（引擎早就支持多字体注册、多纹理页、逐字 `xadvance`），
  而是**两个外部条件**：一张几 MB 的中文字形图集，以及它的许可证。

## 背景：三条路，代价差得很远

| 路线 | 怎么做 | 代价 |
|---|---|---|
| A. 用系统/网页字体渲染 | 让浏览器 `fillText` 出图再打包 | **不可复现**：Linux runner 上没有中文字体，`fillText` 会静默产出另一张图，而判据全绿（这是批66 就写进文件头的理由） |
| B. 取一个像素 TTF 自己栅格化 | Zpix（MIT）/ 方舟像素（OFL）都在这一档 | 要引光栅化器（FreeType / canvas），于是"同一份输入不同字节"的来源又多一层；`--check` 逐字节比对会变成"同一台机器上才行" |
| C. 取**原生位图** BDF | 直接读位，不栅格化 | 满足条件的字体极少：要有 BDF + CJK 全覆盖 + 允许商用与再分发 |

选 C。这不是"更正统"，是因为它是唯一**没有光栅化器**的路线 ——
生成链里少一环，`node tools/make-ui-assets.mjs --check` 才有意义。

## 决策

### ① 用 GNU Unifont 18.0.01，按 **OFL-1.1** 那一条许可

上游自 13.0.04 起**双许可**：`SIL OFL 1.1` 或 `GPLv2+ 附 GNU 字体嵌入例外`。
取 OFL 的理由很具体：GPL 那条的例外只覆盖"把字体**原样**嵌进文档"，
而我们要分发的是**改过的派生图集**（子集化 + 重新打包成 BMFont）。
OFL 明确允许修改与再分发，条件只有三条，都好满足（见 ②）。

选 Unifont 而不是别的：**BDF 是它的原生格式**（不是从 TTF 转出来的），
覆盖全部 BMP（GB2312 的 6763 个汉字一个不缺），16×16 的正方形汉字格与 2.5D 像素风一致。
代价是它"只求有字形、不求好看"，小字号下偏凑 —— 这是可接受的：
UI 文案只有几个字，而"能显示"与"好看"是两个批次的事。

### ② 三条 OFL 义务，各有对应做法

| 义务 | 做法 |
|---|---|
| 随分发带版权声明与许可原文 | `vendor/unifont/{LICENSE.txt,OFL-1.1.txt}` 原样入库，`SOURCE.md` 记 URL / 字节数 / sha256 |
| 衍生字体不得用保留字体名 | 上游未声明保留名；仍把产物改名为 `unifont-cjk-16-subset`（判据钉着 `.fnt` 的 `info face`） |
| 衍生字体同样以 OFL 分发 | 本文件 + `SOURCE.md` 记明 |

### ③ `vendor/` 存**上游原样文件**，不存"我们处理过的版本"

`vendor/unifont/unifont-18.0.01.bdf.gz`（1259315 字节，sha256 `2989e021…`）一个字节没改。
理由是**可核**：任何人拿上游 URL 重下一次，`sha256sum` 对得上就说明生成链的输入没被动过。
存"处理过的子集 BDF"会小很多，但从此"这份文件和上游什么关系"只能靠人记。

### ④ 只打 `tools/cjk-charset.txt` 里声明的字符集，不整字库

Unifont 有 57086 个字形。全打进去的图集大十倍，而**"四万多个字永远不出现"这件事在产物里
看不出来** —— 于是没人会去删。反过来，字符集是仓库里一个可 diff 的文本文件，
它有两条判据守着：`字符集里的每个字在图集里都有墨`（正向）与
`图集里的字形数 = 字符集大小`（反向，防止图集里冒出没人要的字）。

当前内容是**可打印 ASCII + GB2312 全集**（6763 汉字 + 682 符号）。选 GB2312 而不是
"GBK"或"常用3500字"，是因为它的码位范围是确定的（`0xA1A1..0xF7FE`），
所以这份清单可以用三行代码重新算出来并核对（7431 个有效码位，无歧义）；
而"常用3500字"这种说法每个字表都不一样，等于把判据交给一个说不清出处的清单。

### ⑤ 中文是**第二张字体**，不是"5×7 里多塞一批字"

汉字要 16×16 的格，塞不进 5×7 的单元格；把 ASCII 也换成 Unifont 的 8×16，HUD 三行会
突然高 60% —— 那是**改版**，不是"支持中文"。所以：两张图集、两个 `.fnt`、两个字体 id，
节点用 `props.fontId` 选。背包行换成 16px 字，行高跟着从 14 变 22（判据钉着这两件事
是同一个决定）。

### ⑥ 页号分两层：`.fnt` 里恒为 0，全局页由宿主给（`parseBmFont({ pageBase })`）

BMFont 的 `page id` 是**字体局部**编号 —— 造字工具导出来的单页字体都写 `page id=0`。
而一个 UI 模块的 `pageSources` 是**全局**数组（0=5×7 字形、1=皮肤、2=中文字形）。
这两层之间必须显式换算。

第一版没有这一层，我让生成器直接写 `page id=2` —— 结果 `.fnt` 里只有一条 page 行却是
`id=2`，解析器判它"引用不存在的页"（自相矛盾的资产）。**资产要合规范，换算就该在读取方。**

### ⑦ UI 页不进编辑器的**世界**图集

中文字形图是 1024×2092。它一进编辑器的世界图集，`buildAtlasFromSources` 就因为单帧超过
`maxSize=2048` 失败 ⇒ 整个编辑器退回**程序化假贴图**：10 张真图一张都没进图集，
而画面上"世界照样有树有石头"（那是兜底），只有"图集来源"那一栏从 `assets` 变成 `procedural`。

所以按名字前缀（`ui-`）把它们挡在世界图集之外。用前缀而不是"清单里加个字段"：
前缀是约定，改名也漏不掉；字段要靠人填对，填错了照样炸。

## 代价

| 项 | 量 |
|---|---|
| 仓库体积 | +1.26 MB（上游 BDF，压缩态）+ 710 KB（`.fnt` 文本）+ 344 KB（图集 png） |
| 生成耗时 | +约 1.0 秒（解压 9.4 MB BDF + 解析 5.7 万字形） |
| 判据耗时 | +约 1.5 秒（`ui-cjk-font` 15 条，含一次完整生成与逐位比对） |
| 图集尺寸 | 1024×2092（单帧），占 GPU 显存 8.5 MB |
| 打包分包 | `web/assets` 打包从 1 个 `.pack` 变成 4 个（打包器按 64KB 切，单体超限的自成一包） |

## 不做的三件（各有具体理由，不是"以后再说"）

- **不做字形缩放/多字号**。位图字体放大就糊，这是它的固有代价；要 24px 的中文就再生成一张
  图集。自动挑"差 2px"的字体是 `FontRegistry` 明确拒绝的事（见它的注释）。
- **不做字形美化**。Unifont 的目标是"每个码点都有东西"，不是好看。要好看得换字体 ——
  那是换资产，不是改代码，而换资产的成本正好由本 ADR 的 ③ 承担（换 `.bdf.gz` + 改
  `SOURCE.md` + 重跑生成器）。
- **不做按需加载（字节码字体）**。`font-subset` 那套（只带用到的字的子集）能让首包小很多，
  但它把"图集是构建期产物"变成"运行时产物"，那条逐字节可复现的保证就没了。
  当前 344 KB 的图集对桌面端与 demo 都不构成压力，等真做小游戏分包时再谈。
