# ADR-0007 · 资产身份在 `.meta` 里；导入产物与源文件分离

- **状态**：已采纳（由 `tests/extensions/asset-import.test.ts` 与 `asset-loaders.test.ts` 强制）
- **日期**：2026-10-22

## 背景

上一代引擎最贵的一笔债是"资产没有身份"：场景文件里写 `evergreen\t4.000\t0.000`，
用 **prefab 名字**当标识。后果是一整串：

- 改名字 = 删旧建新，所有引用**静默**失效；
- 不能算依赖（谁用了这张图？）⇒ 不能增量导入、不能分包；
- 不能重命名、不能在两份同名资产间选择；
- "换一张贴图"只能改代码。

`AssetDatabase` 已经有 `AssetId`（GUID 风格）与依赖图，但**没有身份的来源**：
id 从哪来、存在哪、源文件改名后还在不在，都是空白。

同时有个实际矛盾要解决：
- `stableIdFromPath(path)` 可复现（同一文件重导入两次得到同一个 id），**但改路径就换 id**；
- 而"改路径不该换 id"正是不用路径当标识的原因。

## 决策

### ① 身份写在源文件旁边的 `.meta` sidecar 里

`assets/grass.png` → `assets/grass.png.meta`：

```json
{"id":"p1mrska0","type":"texture","importerVersion":1,"settings":{}}
```

- **首次**：id 由逻辑路径派生（`stableIdFromPath`，可复现），并写入 `.meta`；
- **之后**：一律以 `.meta` 里的 id 为准。

于是"移动/改名"只要 `.meta` 跟着文件走，id 不变 —— 引用不断。
这也是 Unity/Cocos 的做法；区别只是我们的 id 是 base36 短串（可读、可 diff）。

### ② 导入产物放在 `library/imported/<id>.json`，与源分离

产物是 `{type, importerVersion, sourceHash, byteLength, dependencies, data}`，
写入时字段顺序固定 + 2 空格缩进 + 末尾换行 ⇒ **同输入同字节**。

- 源文件是**人写的**（可能被手改、被美术替换）；
- 产物是**机器写的**（可以整个删掉重建）；
- 把两者混在一起会让"清理产物"变成"清理资产"的高危操作。

### ③ 增量判定 = `sourceHash` + `importerVersion`，两者都相同才跳过

- 内容变了 → 重导；
- **导入器逻辑变了**（`importer.version` +1）→ 即使内容没变也重导。

少了后一半，症状是"修了导入 bug，但老产物一直在用，看起来没修好"。

★ 还有一个必须一起判的：**依赖仍然活着**。
产物只记录"上次解析出的 id 列表"，依赖文件可能已被删。
只看源 hash 的话，图集会一直命中旧缓存，缺依赖永远不报 ——
这就是"删了一张贴图，构建全绿，运行到加载才崩"。

### ④ 无 importer / 缺依赖 / 坏 `.meta` 一律进报告，不静默跳过

`ImportReport.failed` 逐条给出 `{path, code, message}`，且**单个失败不中断整轮**：
一个坏 PNG 不该让整个工程导不进来。
但"报告说全部成功、实际少了一半资产"是不可接受的，所以未知扩展名也是失败项。

### ⑤ 反注册与清理

源文件删除后，`AssetDatabase` 里会留下幽灵条目。`unregister(id)` 的两条拒绝条件
都不是保守而是正确性：

- `refs > 0`：有句柄在用，删了句柄指向已释放实例；
- 有反向依赖：删了它，依赖方下次加载失败，而失败点离根因很远。

管线只在"本轮至少一个资产注册成功"时才做清理 ——
否则 `root` 写错（扫到 0 个）会变成"把整个资产库从注册表抹掉"。

## 后果

### 正面

- 改名/移动保 id（判据：`移动/改名保 id`）。
- 同输入同字节（判据：`幂等：第二次 run 全部 skipped，产物逐字节不变`）。
- 依赖顺序 = 声明顺序（不排序：顺序是加载顺序的确定性来源）。
- 删除源文件后的清理是**可判定的**（`removed` 计数 + `STILL_REFERENCED` 点名依赖方）。

### 代价 / 已知边界

- **texture importer 只解析 PNG 头**（宽/高/位深/色彩类型），不 inflate 像素。
  像素解码归 `gfx` 后端（浏览器 `createImageBitmap` / Node `zlib`）。
  在 L4 手写一份 inflate 是重复劳动且更慢。
- **产物路径规则是导入器的实现细节**，所以加载器由 `createImportLoaders({ root })`
  构造时拿到根目录，而不是从 `AssetMeta.path` 反推 —— 反推等于用隐式约定绑两处代码。
- **孤儿 `.meta` 不自动删**：源文件被删但 `.meta` 残留时，管线不会替你删它
  （可能是用户正在编辑的资产，误删比留着贵）。这一步留给编辑器（阶段 4）。
- **`settings` 目前恒为 `{}`**：按类型的导入设置（过滤模式、图集打包参数）还没有 UI，
  结构已预留。
- **纯删除的清理依赖 `registered > 0`**：全轮导入失败时不做清理（保守，宁可留幽灵）。

## 备选与为什么没选

| 备选 | 否决理由 |
|---|---|
| 用文件路径当 id | 就是上一代的债：改名断引用，无法算依赖 |
| 用内容哈希当 id | 内容一改就换身份，引用全断；"换一张贴图"会变成新资产 |
| id 存在中心索引文件（`assets.json`） | 多人协作时该文件天天冲突；sidecar 的冲突面只有自己那个文件 |
| 产物直接覆盖源文件旁边 | 清理产物 = 高危操作；且源目录被美术工具扫描时会看到一堆机器文件 |
| 增量只看 mtime | 拷贝/检出会改 mtime（git 不保存它），于是"改一个文件全量重导" |
