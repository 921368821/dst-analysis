# ADR-0010 · 补间（tween）：为什么先做"两条纯函数"，以及为什么独立成 `extensions/tween/`

- **状态**：已采纳（由 `tests/extensions/tween.test.ts` 38 条判据强制；变异 M293–M302 证明判据不空转）
- **日期**：2026-10-25
- **背景**：P0-1（UI + 位图字体）交付后，产品侧四件套里三件已起步
  （构建 CLI / 编辑器最小闭环 / UI），**动画是唯一还完全为 0 的**，
  而它同时被两处依赖：UI 的"过渡动画"（PROGRESS §六 P0-1 缺口表）与
  战斗表现层的 hitstop / 受击位移（批69 只做了闪色与挤压，没有时间轴）。

## 背景

引擎里**已经有**一段动画时间轴 —— `render/animation.ts`（`AnimationClip` +
`sampleClip`，批52 为 APNG 帧序列交付）。它回答的是"时刻 → 第几帧"，
是**离散**的。缺的是另一半："时刻 → 一个数"，即对任意标量属性
（位置、缩放、透明度、颜色分量）的**连续插值**。

两者不是同一件事的两种写法：帧时间轴的循环天然回到第 0 帧，
而补间的 `from ≠ to`，循环边界回到 `from` 会是可见的跳变。
硬把补间塞进 `AnimationClip`（例如"帧名里编码数值"）会得到一套
既不能序列化也不能校验的中间层。

## 决策

### ① 新建 `src/extensions/tween/`，不放 `render/`

`render/` 下已有 `animation.ts`。再放一个 `tween.ts` 会出现两个
"动画"概念共处一目录，而它们的消费者不同：帧时间轴只服务渲染，
补间同时服务 **UI（`extensions/ui/`）** 与**战斗表现（`extensions/render/feedback.ts`）**。
按仓库既有的 `inventory` / `combat` / `crafting` / `nav` 先例，
被多个域消费的东西独立成扩展。

命名用 `tween` 而不是 `animation`：前者精确指"属性补间"，
后者在工业界已承载"状态机 + 混合 + 骨骼"一整棵树，现在占这个名字
会让后来的完整动画系统无处可放。

### ② 本批只交付两条纯函数，不交付组件/模块

| 文件 | 层 | 为什么先做它 |
|---|---|---|
| `easing.ts` | 缓动函数族（31 条） | 纯函数，可被 Node 判据全覆盖；是"手感"的唯一来源 |
| `tween.ts` | 单个标量补间（构造 + 采样） | 同上；且 UI 过渡与 hitstop 都只需要这一层 |

**不做的**（记入缺口，不是遗漏）：属性轨道（一条属性 × 多关键帧）、
混合（多段同时写同一属性）、`TweenPlayer` 组件、`setOverlay` 之外的
每帧驱动接线。理由：这三件都要先有"跨帧状态位"的设计
（`UiNode` 上开状态、与 `SpriteAnimator.timeMs` 怎么共存），
而在没有消费者之前先把状态位设计出来，只会得到一套猜出来的 API。
**先把纯函数做对，让第一批消费者来定义状态位。**

### ③ 采样是纯函数、不持状态、不缓存"上次时间"

与 `sampleClip` 完全同源。共用一个消费者群：渲染、UI、回放校验、
调试面板会各自采样。纯函数让它们互相不可见；一旦缓存"上次时间"，
seek 之后的第一帧会取决于缓存的陈旧值。

### ④ `from`/`to` 必须显式，不允许采样时读"当前值"

读当前值 = 起点随调用时机漂移。同一段配置 `0→100` 的补间，
第二次从 80 开始播，实际就成了 `80→100`，而配置里写的仍是 `0→100`。
症状是"时长一样、幅度越来越小"，极难归因。

### ⑤ 三条时间口径（都写成了判据）

| 字段 | 口径 | 反模式 |
|---|---|---|
| `delayMs` | **只在第一次**生效，循环内不重复 | 循环内重复会让节奏变成"停-走-停"，与 CSS `animation-delay` 也不一致 |
| `speed` | 只做两件事：缩放一段的换算时长；`<0` 时把进度取反（倒放）。**不在调用方之外再缩放一次** —— 调用方负责 `timeMs += dt * speed` | `speed=0` 在采样里除零得 Infinity ⇒ 循环号恒 0 ⇒ 与 `speed=1` 行为分叉 |
| `yoyo` | 奇数轮把进度翻过来，用**同一条** easing（`easing(1-p)`）。与 `speed<0` 是**异或**关系 | 把 easing 换成镜像函数 ⇒ 得到另一条曲线，去回不再对称；异或写成叠加 ⇒ 往返轮方向整体反了 |

### ⑥ 循环边界：进度与方向都要按"上一轮"算

`t` 恰为 `duration` 整数倍时，轮号已经 +1。此时
① 进度必须取 1（上一轮刚结束）而不是 0，否则每隔一个 duration
画面就闪一下 `from`；② 若 `yoyo` 开着，方向也必须按上一轮判，
否则这一帧会被算成反向轮而给出 `from` 而不是 `to`。
同一处两个半条，分别由 M297 / M298 钉住。

有限循环播完停在**最后一轮的终点**：最后一轮编号 `loopCount-1`
是奇数 ⇒ 反向 ⇒ 停 `from`。无条件停 `to` 会让"往返 4 次"的动画
停在 100，而肉眼看到的最后状态是 0。

## 为什么先写判据再写实现（本批的实际过程）

第一版 `easing.ts` 的 elastic 相位偏移用了 `0.1`，而 `t=0`/`t=1`
都有端点特判 —— **端点判据全绿**，只有 `inOut` 的中心对称判据
把它咬出来（中点漂到 0.567）。这条教训已固化成 M295：

> 端点特判与公式正确是**两条独立的保证**，少一条另一条看不见。

同批还修掉三处判据自身的错（bounce 落点表、`speed=0` 的输入不合语义、
"不回落 linear"用字符串包含去测），以及两处 IEEE 边缘
（`0 × 负数 = -0`、`1-cos(π/2) = 0.9999999999999998`）。

## 缺口（不在本批）

- 属性轨道（多关键帧）与混合：需要先定 `UiNode` / `SpriteAnimator` 上的跨帧状态位
- `TweenPlayer` 组件与每帧驱动：等第一批消费者（UI 过渡 or hitstop）来定义
- 自定义曲线（贝塞尔/美术编辑）：要进注册表必须通过同一组性质判据
- `holdMs`（轮间停顿）：`delayMs` 刻意不做这个，避免一个字段两种语义
