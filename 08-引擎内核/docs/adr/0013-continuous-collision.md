# ADR-0013 · 连续碰撞（扫掠）：要的是「时刻」不是「重叠」，精确解 = 放大盒的四条边 + 四个角圆

- **状态**：已采纳（`tests/extensions/physics-sweep.test.ts` 26 条 + `tests/extensions/ai-move.test.ts`
  的 3 条接线判据强制；变异 M508–M522 证明判据不空转）
- **日期**：2026-10-27
- **背景**：阻塞清单 C6。`resolve()` 按**当前**坐标找重叠对 —— 对"一拍之内从墙这侧到那侧"
  完全无能为力：跨过去之后两侧都不重叠，下一拍再也不会被推开。
  症状是「这只怪偶尔穿过箱子」，而且同一个种子复现不了：穿不穿取决于
  `speed × dt` 与墙厚的乘积，只有某一帧正好够宽时才发生。

## 背景：这个决定难在哪

难点不是"要不要扫掠"，而是**扫什么几何**。最省事的做法是把盒子放大 `r`（Minkowski 和的
正方形近似）再和线段求交 —— 二十行写完。它在四个角上多出一块，症状是"贴着角走会提前停住"，
而那块多余区域只有 `r(1 - 1/√2) ≈ 0.29r` 宽，看起来像"手感有点黏"。

实测的差（`physics-sweep.test.ts` 里有判据钉着）：

| | 盒 2×2 在原点、`r = 0.5`，沿 45° 从 `(-2.5355, -2.5355)` 打向近角 `(-1,-1)` | 接触时刻 |
|---|---|---|
| 放大盒 | 入口在半宽 `1 + 0.5 = 1.5` 处 | `t = 0.1464` |
| 精确解 | 起点到角 `(-1,-1)` 距离 `2.1716`，减去 `r` | `t = 0.16716` |

早了 `0.02`（≈ 0.21 个世界单位）—— 走得到却先停住。反过来，放大盒还会把
「离角还有 0.136 没碰到」误报成 `t = 0`（"已经重叠"），于是那一步**整拍不动**。

## 决策

### ① 精确解 = 放大盒的四条边 ∪ 四个角圆

四条边（真正的外表面）只在**接触点落在原盒该边的范围之内**时有效，剩下的角区域交给
以角点为中心、半径 `r` 的圆。两半合起来正好是 Minkowski 和（圆角矩形），没有近似。
实现里"角区域"的判定就是一行范围检查（`other < f.lo || other > f.hi ⇒ 跳过这个面`）。

### ② 起点已重叠 ⇒ `t = 0`，法线取**穿透最浅**的那条轴

不是"沿位移反方向"。压在盒子中间往右走时，位移反方向可能指向一面 4 个单位厚的墙，
而最浅的那面只差 0.3 —— 沿最浅的推出去才是"这个位置最省力的解释"。
`t = 0` 的语义是"**这一拍不许动**"，由调用方（`moveSwept` / AI 移动）兑现。

### ③ 零位移 + 不重叠 ⇒ `null`，不出 `0/0`

`t = 0/0` 是 `NaN`，而 `NaN` 会顺着"取最早命中"的比较一路污染：`NaN < best` 恒为 false，
于是"这一步有障碍"变成"没有障碍"。零位移单独短路。

### ④ 擦过用严格 `>`：距离恰好等于 `r` 算接触

`>=` 与 `>` 的取法决定了"贴面滑行时会不会粘住"。选"接触"是为了让下一拍能正常滑；
选"不接触"会让贴面滑行的体偶尔陷进去半个半径。

### ⑤ 只扫**静态**体

动态体撞上之后 `resolve()` 会把两边分开；扫掠一遍反而会让**两只怪互相卡住**
（A 扫到 B 停下、B 扫到 A 停下，谁都不动 —— 而它们本来是能挤过去的）。
"解算永远救不回来"这件事只对静态障碍成立。

### ⑥ 只回答、不改位置

`sweepMove` 返回 `{t, nx, nz, nodeId}`，位置由调用方写。理由：要不要停、要不要滑、
要不要顺便播个撞击动画，只有调用方知道；而"改位置"的库函数没法被行为树/感知复用。

### ⑦ 滑动 = 去掉位移的法向分量，且路程恒 ≤ 原长

`d = (d·n)n + 切向`，去掉前者正好贴墙。**不许重新给满步长** —— 那会让贴墙走比直线更快
（凭空加能量），而症状"贴着墙走更快"几乎没人会怀疑碰撞代码。`traveled` 只累加真实走过的段。

### ⑧ 候选集用**圆**的保守范围

`query(起点, |d| + r_self + maxRange)`，不是轴对齐方框范围：方框会漏掉斜方向的候选，
而漏掉的症状正是"偶尔穿过去"，与这段代码要修的问题一模一样。

### ⑨ 接线在 AI 移动：夹到接触点之前，被挡住不推进游标、不宣布到达

`createMoveModule` 的 `sweep` 选项（结构化类型，不 import 物理层）。三个后果各有判据：

- 夹住 ⇒ 圆心不越过 `墙面 - r`（对照：不注入 `sweep` 时同一夹具会穿过去）；
- 游标不前进 ⇒ 不会"贴着墙把剩下的路空走完"；
- 被挡住不宣布到达 ⇒ `r.done` 的含义是"预算走完了这条路"，不是"人走到了"。

停在接触点**之前**留 `SWEEP_SKIN = 1e-3`：恰好相切在浮点上是五五开，下一拍可能把 `t` 报成
`0`（"起点已重叠"），表现成"被墙吸住、推都推不动"。

## 不做的事

- **不用放大盒**（见背景里的数字）。省二十行的代价是"手感发黏 + 角上假重叠"。
- **不让 `sweepMove` 顺手推位置**。见 ⑥。
- **不做胶囊体 / 连续旋转**。当前所有体的形状是"圆或轴对齐盒"，旋转盒的扫掠是另一件事
  （要加 SAT + 扫掠对时间求交），而目前没有内容需要它。
- **不接管 `resolve()` 的职责**。起点已重叠这件事交给位置解算分开；扫掠的职责是
  "别让重叠发生"，不是"把重叠解决掉"。混在一起会让两层互相打补丁。
