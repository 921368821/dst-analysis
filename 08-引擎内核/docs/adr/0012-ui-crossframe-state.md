# ADR-0012 · `UiNode` 的跨帧状态位：派生与权威分开、键用 `uid`、两个失效入口

- **状态**：已采纳（`tests/extensions/ui-state.test.ts` 20 条 + `tests/extensions/ui-intrinsic.test.ts` 19 条 +
  `tests/extensions/tween-keyframes.test.ts` 20 条强制；变异 M485–M507 证明判据不空转）
- **日期**：2026-10-27
- **背景**：ADR-0010 把「属性轨道（多关键帧）与混合」标成缺口，理由写得很清楚 ——
  「这三件都要先有**跨帧状态位**的设计」。同一句话也压着另外三件：富文本 / 避头尾 / RTL、
  滚动容器、标签自撑开。四件事卡在同一个前置决定上，这是清单里唯一的一对多。
  本文只回答那一个决定，不顺带实现四件（其中两件在本批落地，两件留缺口，见文末）。

## 背景：这个决定难在哪

难点不是"要不要缓存"，而是**状态的归属**。UI 里跨帧要记住的东西有两种，长得像、性质相反：

| | 例子 | 丢了会怎样 | 能不能重算 |
|---|---|---|---|
| **派生** | 一段文本排出来几行、多宽、缺哪些字 | 下一帧重排一次，看不见 | 能（只由字体/文本/样式决定） |
| **权威** | 滚动容器的偏移、补间的进度 | 用户回到顶部 / 动画从头播 | 不能（由用户操作与时间决定） |

三种错误写法各自都有明确的症状：

- **挂在 `UiNode` 上**：`UiNode` 是可序列化的配置（编辑器要能存、能复制、能 diff）。
  `scrollY` 写进去之后，存档里就有"上次滚到哪"，而那个数字在换分辨率/换界面之后毫无意义，
  却会被当成配置带到下一个版本。
- **只留一个 `clear()`**：清得少 ⇒ 换了字体滚动位置莫名回顶；清得多 ⇒ 热重载字体时
  用户正看着的列表跳回顶部。**两种症状都像"随机的 UI 抖动"**，而根因在失效规则。
- **按 `id` 做键**：`id` 是配置字段，可以重名、可以改。改了 id 之后状态跟过去 = 串到别人身上
  （"改了个 id 结果列表滚到了另一块"）。

## 决策

### ① 状态放 `UiStateStore`，不进节点、不进存档

`src/extensions/ui/state.ts`。表的所有者是 UI 模块（`createUiModule` 里一个实例），
与 `UiNode` 生命周期无关：节点被销毁时由 `drop(uid)` 清，换界面/回滚时 `reset()`。

### ② 键是 `uid`（构造时分配的单调整数），不是 `id`

`uid` 从不复用 ⇒ "旧节点的状态绝不会被新节点读到"是**结构上**成立的，不靠清理纪律。
代价是"重名 id"侦测不到 —— 那是另一件事（`layoutTree` 里对 `id` 重名已经有抛错）。

### ③ 两个失效入口，不共用一条规则

| 入口 | 清什么 | 谁调用 | 为什么 |
|---|---|---|---|
| `invalidateDerived()` | 只清派生（文本量算） | 字体表变更（`FontRegistry.onRegister`） | 换字体不该让用户正在看的列表回顶 |
| `reset()` | 派生 + 权威，并把 `epoch` +1 | 换界面（`setRoot`）、dispose | 上一份世界的滚动位置不该被这一份读到 |

`epoch` 单调自增。它现在只用于诊断（"两次报错之间没变过 ⇒ 不是缓存导致的"），
但它让"任何绕过表的人"也有机会自查过期，而这件事在一张没有版本号的表上做不到。

### ④ 自然尺寸由**布局注入口**提供，不在布局之外再走一遍

`layoutTree(root, bounds, { intrinsic })`：布局在**内区尺寸已经算好**的那一刻问一次
「这个叶子的自然尺寸是多少」，答案写回 `node.contentSize`（于是诊断面板和下游公式都能看见）。

不这么做的替代方案是"画之前先自顶向下量一遍"，但那要把 `measure()` 的约束传播抄第二份；
两份迟早不一致，症状是"文本有时溢出边框一点点"，只在特定嵌套深度出现。

同一条理由也决定了 `textBoxOf` / `textStyleFor` 必须**绘制与量算共用**：
换行宽来自同一个函数，所以"盒子按 A 宽排、字按 B 宽折"这类错在结构上不可能发生。

### ⑤ 没有显式宽时**不换行**（收缩到内容，不是撑满一行）

CSS 里 `width: auto` 与 `width: 100%` 的差别。默认必须是前者：
否则一个没给宽度的标签会撑满整行，同一段文字在长面板里换行、在短面板里不换行，而作者什么都没写错。

由此得到一条**结构性**不变量（不是巧合，靠内缩与内边距留出的余量保证）：
**自撑开的节点在按测量宽绘制时必然不换行。**

### ⑥ 字体表变更由注册表自己通知

`FontRegistry.onRegister(cb)`。文本排版结果里**烘进了字形来源**（`page` 下标、UV、`xadvance`、kerning）；
热重载一个同 id 的字体之后，旧缓存指向旧图集 —— 画面上是一堆乱码，而布局量出来的宽高还是旧的。
"让每个注册点记得清缓存"是不可靠的（启动、编辑器导入、热重载三处），所以通知从**改表的那一处**发出。

### ⑦ 关键帧轨道与分段轨道是**两个数组**，不把 `TweenSpec` 变可空

`TweenPlayer.keyTracks` 与 `TweenPlayer.tracks` 并列，`advancePlayer` 各一个循环。
让 `spec` 变可空的话，`speed`/`loopCount`/`durationMs` 的十几个读点都要判空，
而**漏判不会报错** —— 只会静默按"没有 speed"处理（永不推进）。
两种类型不同的数组让"这是哪种轨道"在类型层面成立。

## 本决定解锁了什么（四项里的两项）

| 项 | 状态 | 落点 |
|---|---|---|
| 标签自撑开 | ✅ 本批 | `ui/intrinsic.ts` + `LayoutOptions.intrinsic` |
| 补间属性轨道（多关键帧） | ✅ 本批 | `tween/keyframes.ts` + `TweenPlayer.addKeyTrack` |
| 滚动容器 | ⏳ 未做 | 状态位与 `scrollOf/setScroll` 已经在了，缺的是"输入 → 偏移"与 CPU 侧裁剪 |
| 富文本 / 避头尾 / RTL | ⏳ 未做 | 需要 CJK 度量（先有 C8 的字体图集）才谈得上避头尾；RTL 还要双向算法 |

## 仍然不做的，与理由

- **多轨混合写同一属性**：需要一个按属性语义决定"乘 / 加 / 覆盖"的解析器。
  现在只有一条确定的顺序（分段轨道在前、关键帧在后，后者胜），这不是混合。
  在没有第二个消费者之前定它，只会得到一套猜出来的 API —— 与 ADR-0010 ② 同一条理由。
- **关键帧轨道的循环与速率**：`yoyo` 在分段轨道上是"逐段翻向"，在关键帧轨道上只能是"整条重播"，
  两个语义塞进一个字段必然有一边的人理解错。要循环就再挂一条同样配置、从 0 重播的轨道。
- **把滚动偏移写进存档**：与 ① 直接冲突（那正是这一条要防的东西）。要做"记住背包滚到哪"，
  应当存进**界面状态**（由应用侧自己管），而不是节点或这份派生表。
