# ADR-0002 · GPU 资源用不透明句柄，不用对象引用

- **状态**：已采纳
- **日期**：2026-10-22

## 背景

图形 API 里"资源"在三种后端上形态完全不同：
WebGL 是 `WebGLTexture` 对象、Vulkan/Metal 是裸指针或索引、wasm 里是线性内存偏移。

如果接口返回对象（`ITexture`），会依次出现三个问题：
1. 调用方可以 `as any` 拿到后端的私有字段和方法，抽象直接漏了；
2. 销毁后对象仍然"存在"（只是内部失效），于是"用已释放资源"变成偶发崩溃或静默画错；
3. 后端必须为每个资源维持一个 JS 包装对象，多一层间接与 GC 压力。

## 决策

返回 **branded number 句柄**：

```ts
export type TextureHandle = number & { readonly [brand]: "Texture" };
const t: TextureHandle = dev.createTexture(desc).value;   // 7
dev.destroyTexture(t);                                    // 之后 7 整体失效
```

设备内部用 `Map<number, Rec>` 维护真实资源，并在销毁时删除记录。
任何对已销毁句柄的操作返回 `GFX.INVALID_HANDLE`（**失败，不是静默忽略**）。

## 后果

### 正面

- 后端可自由选择"对象 / 索引 / 裸指针"—— 接口完全不变。
- 销毁是**整体失效**：不会留下"半死对象"（上一代引擎的"删父后子实体 `_parent` 悬空"就是这类）。
- 句柄可以被序列化 / 记录 / 断言（判据能直接说"这一帧绑了 3 号纹理"）。
- 调用方无法绕过设备，抽象边界是**物理的**（类型上就拿不到后端）。

### 负面

- 每次访问多一次 `Map` 查表。相对于一次 draw call（微秒级），可忽略。
- 句柄值可以跨代际复用（销毁 7 号后再创建可能又是 7 号）。
  **缓解**：设备可以实现"代际号"（高位记代数）来检测 ABA；
  当前未实现，但契约测试只依赖"销毁后的句柄操作必须失败"这一行为，
  将来加代际号不需要改接口。

## 被否的方案

- **返回接口对象**（`ITexture`）：抽象会漏（后端私有字段可被访问），且销毁后对象仍可被传入。
- **返回 `string` id**：字符串比较慢且容易拼错；number 有类型品牌保护。
