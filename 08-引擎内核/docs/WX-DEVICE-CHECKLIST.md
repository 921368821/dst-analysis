# 微信小游戏 · 真机验收清单

> **这份清单只回答一件事**：`src/wx-entry.ts` 与 `tools/wx-check.mjs` 已经能保证的
> 「包能构建、产物不是空壳、没有 ESM / node 内置、禁用 API 0 处」，在**真机**上
> 还剩哪些**只能靠人看**的行为差异。
>
> 它存在的理由：CI 第 11 步（`tools/wx-check.mjs`）验的是**产物侧**，
> 而宿主层有一整类问题只在设备上出现 —— 帧源频率、触摸坐标、文件系统语义。
> 这些不是"没做"，是**没有设备就验不了**（与 `BLOCKERS` 的 B1 同源：上传要 appid/私钥）。
> 所以把它变成两页纸，而不是继续留在"以后再说"里。
>
> **怎么用**：一个机型一张表。每条只有三列 —— 怎么观察 / 期望是什么 / 不一致时先看哪。
> 不一致就是新的一条 `BLOCKERS`，不要在这里就地改代码。

## 0 · 前置

| 项 | 要求 | 没有时 |
|---|---|---|
| 微信开发者工具 | ≥ 1.06，**基础库**与目标用户一致 | 只能跑模拟器，帧源与触摸结论都不可信 |
| 小游戏 appid | 真机预览必需 | 停在模拟器，清单第 1–2 组能看，3–4 组看不了 |
| 真机 | 至少一台 iOS + 一台 Android | 单平台结论必须标注平台 |
| 包 | `npm run build:wx` 产出 `web/wx/game.js` | —— |

## 1 · 启动（最容易「看起来在加载、其实已经死了」）

| 怎么观察 | 期望 | 不一致时先看 |
|---|---|---|
| 冷启动到能操作，**弹窗**出现情况 | **没有**「启动失败」弹窗 | `src/wx-entry.ts` 的 `reportFatal` 文案；日志里搜 `WX.NO_` |
| 控制台第一条日志 | 有 `EngineWx` 相关字样（不是空的） | 产物是不是空壳：`node tools/wx-check.mjs` 会先拦 |
| 断网后冷启动 | 出现**明确**弹窗（不是白屏） | 同上；重点看 `WX.NO_FS` / 资源加载失败有没有被 `reportFatal` 接住 |
| 切后台 5 分钟再回来 | 不白屏、不重复初始化 | 宿主有没有做「重复 `main()`」保护 |
| 低内存机型（≤2GB）反复进出 3 次 | 不闪退 | 纹理/图集释放路径 |

## 2 · 帧源（CI 永远验不到的一层）

| 怎么观察 | 期望 | 不一致时先看 |
|---|---|---|
| 屏幕上 FPS 计数（宿主 HUD 有就开） | 稳定在 55–60，不持续抖动 | `requestAnimationFrame` 是否被包了一层 |
| 切后台再回前台后的**第一帧** dt | 被**钳住**（不出现「世界瞬移」） | 帧源有没有按 `fixedDt` 换时间（`SCHEDULER` 的钳制） |
| 同一场景连续跑 10 分钟 | 逻辑步数与墙钟大致成比例，无累积漂移 | 用 tick 而非帧数计时的约定 |
| 来电中断 / 通知横幅 | 回来后时间不跳变 | 同「切后台」 |

## 3 · 触摸（坐标最容易差一个安全区）

| 怎么观察 | 期望 | 不一致时先看 |
|---|---|---|
| 点右上角按钮 | 命中（不是偏一截） | `src/host/wx/input.ts` 的 `toCanvasPoint`（含 `safeArea` / `devicePixelRatio`） |
| 点左下角按钮 | 命中 | 同上（差常数偏移通常是 `windowHeight - safeArea.bottom` 一类的方向错） |
| 两指同时按 | 不串号、不丢 | 多点触控的 id 映射 |
| 按住拖出屏幕再回来 | 收尾事件不卡住输入 | `touchcancel` 是否当 `touchend` 处理 |
| iOS 刘海屏 / 安卓挖孔屏 | UI **不被遮** | 宿主有没有把安全区传给布局 |

## 4 · 文件系统（存档能不能活过「清缓存」）

| 怎么观察 | 期望 | 不一致时先看 |
|---|---|---|
| 玩一会儿 → 退出 → 重进 | 存档在 | `src/host/wx/fs.ts` 的 `atomicWrite` 是否真的走 rename |
| 强制关闭微信再开 | 存档在 | 是否只在内存里 |
| 清小程序缓存后重进 | 存档**没了**（干净档），不崩 | 首次启动的「无档」路径 |
| 剩余空间很小的机型上存档 | 写入失败时**有提示**，不静默丢 | 写失败有没有被 `reportFatal` 或 toast 接住 |
| 存档后立刻杀进程（1 秒内） | 要么完整、要么没有，**不要半个** | 批132 起是「临时文件 → rename」（`atomicWrite`）；仍要人看一眼：真机 rename 覆盖语义 |

## 5 · 包体与加载

| 怎么观察 | 期望 | 不一致时先看 |
|---|---|---|
| 首包大小 | ≤ 4MB（小游戏主包上限） | `tools/wx-check.mjs` 的体积下限是**下限**（防空壳），上限要人看 |
| 首次进入耗时 | 记录真实值，作为后续基线 | 资源是不是全打在主包里 |
| 控制台报错 | 无 `Unexpected token 'export'` / 无 `require is not defined` | 这两条 CI 已拦（第 11 步），若真机出现说明**真机走的不是那份产物** |
