# 微信小游戏 · 真机验收清单

> **这份清单只回答一件事**：`src/wx-entry.ts` 与 `tools/wx-check.mjs` 已经能保证的
> 「包能构建、产物不是空壳、没有 ESM / node 内置、禁用 API 0 处」，在**真机**上
> 还剩哪些**必须靠设备**的观察项。
>
> 22 条按**证据等级**分三档：**16 条已被可执行判据守着**（真机上只需回归一次，不是“待验”）、
> **3 条只能取数**（帧率 / 耗时）、**3 条只能目视**。逐条论证在
> [`WX-VERIFY-WITHOUT-DEVICE.md`](WX-VERIFY-WITHOUT-DEVICE.md) §1；两份文档的等级由判据
> `tests/host/wx-device-checklist.test.ts` 对账（同编号必须同级、合计必须等于逐行数出的数）。
>
> **怎么用**：一个机型一张表。不一致就是一条 `BLOCKERS`，不要在这里就地改代码。

## 0 · 怎么读等级

| 级 | 含义 | 允许写的结论 | 不一致时先做什么 |
|---|---|---|---|
| **A** | 真机差异已被下游不变量吸收，且有判据 | 「已断言」 | 是**回归**，先跑 `npm test`，不是“设备差异” |
| **A-** | 同 A，但剩下一个**契约假设**（如 `clientX` 的原点） | 「已断言（假设 X）」 | 同上；假设不成立要单开一条阻塞 |
| **B** | 需要一个设备上才有的标量 | 「不掌握」+ 留空 | 去取数，**不许填估计值** |
| **C** | 需要一次设备上的经验观察 | 「未验」 | 去看，**不许写“应该没问题”** |

**A 类不必逐条打勾** —— 它的作用是「改了渲染 / 输入 / 存档之后回来回归一次」，全绿就跳过；
只有不一致才在 §6 记一行。
