### 18.7 ★ 收紧一条**过松**的判据（假阳性三连）

T44 改完文档后，`audit_doc_numbers.py` 报了 3 处「断言条数不符」，**全是假阳性**：

|---|---|---|

|---|---|---|
| `**999 条断言，0 失败**` | 报 | **报** ✔ |
| `共 999 条断言` | 报 | **报** ✔ |
| `本阶段补了 5 条断言。` | 不报 | **没报** ✔ |
| `有 3 条断言全部报红。` | 不报 | **没报** ✔ |

⇒ **判据太松和太紧都要付代价**：太松 = 假阳性淹掉真问题；太紧 = 漏。
这次是「太松」，而且**假阳性本身会消耗注意力** —— 3 条假的比 0 条更容易让人

## 二十七、T17 为什么「不存在」—— 两套编号的冲突，以及修复（T20 轮次；**未记精确分钟，故不写时间**）

## 二十八、★ 自检样本**不能硬编码绝对时间**（跨日才发现）

### 28.1 现象

跨过零点后（10-15 → 10-16），06 的三件套突然报：

```
✘ 规则自检不过 —— 以下规则**没有响**（可能已被绕过或删掉）：未来时间戳
```

而规则**本身是好的**、文档**也没有过期数字**。是**自检自己坏了**。

### 28.2 真因

第 5 条规则（未来时间戳）的**合成样本**是硬编码的：

```python
('未来时间戳', '## 生成时间：2026-10-15 23:59，`date` 实读'),
```

写这段时（10-15 当天）它确实是**未来**；到了 **10-16**，它成了**过去**
⇒ 规则正确地**不响** ⇒ 自检（「喂进去必须被抓到」）**误报「规则没响」**。

### 28.3 修法

样本改成**相对当下生成**：

```python
('未来时间戳',
 '## 生成时间：%s，`date` 实读'
 % (datetime.datetime.now() + datetime.timedelta(hours=2)).strftime('%Y-%m-%d %H:%M')),
```

### 28.4 ★★ 这条值得单记：**会随时间自己失效的自检，比没有自检更糟**

- 它**没有**让漏检发生（规则本身是好的），
  但它会让**红线变成噪声** ⇒ 训练人「看到 ✘ 先怀疑工具」⇒ 下一次真的坏了没人看。
- 这与今天早些时候的「**假阳性三连**」是**同一类代价**：
  **假阳性 = 消耗注意力 = 让人开始忽略工具。**

**推广的规矩**：合成测试样本里凡是**与时间有关**的（未来 / 过期 / 距今多久），
**一律相对 `now` 生成**，绝不硬编码绝对值。

> ★ 顺带说明这条自检**是有效的** —— 它真的发现了自己的样本过期。
> 「自检能发现自己的问题」本身就是它在工作的证据。
