# HTML 动画播放器 + 跨包配对修正

> 目标：让「看到生物动起来」这一步落地（本机没有 LÖVE2D，改用浏览器 canvas）。

## 1. 播放器做了什么

把导出的动画数据 + 解码后的图集，塞进一个**自包含的 HTML**，
用 canvas 实时播放。产物 `_out/anim_player.html`（6.4 MB）。

```
DST 的 anim.zip
   ↓ tools/ktex.py          KTEX + DXT5 → PNG
   ↓ tools/export_json.py   build+anim → JSON
_out/json/*.json  +  anim_data/*.png
   ↓ tools/build_player.py  内嵌成单文件 HTML
_out/anim_player.html         ← 浏览器打开即播
```

功能：生物切换、**30 个动画可选**、播放/暂停、帧滑条、0.25×–2× 倍速、包围盒显示。

## 2. ★ 渲染做法：仿射映射，不是逐三角形光栅化

Python 侧的 `render_host.py` 是逐像素重心插值光栅化（慢，但精确）。
浏览器里没必要那么做 —— 每个符号帧是 6 个顶点（两三角形、非索引），
它们来自**一个矩形做仿射变换**，所以目标形状必然是**平行四边形**。
于是可以直接用 canvas 的 `setTransform` 把 UV 矩形映射上去：

```js
const A = (X1-X0)/sw, B = (Y1-Y0)/sw;   // UV 的 u 方向 → 屏幕
const C = (X2-X0)/sh, D = (Y2-Y0)/sh;   // UV 的 v 方向 → 屏幕
const E = X0 - A*sx - C*sy, F = Y0 - B*sx - D*sy;
ctx.setTransform(A,B,C,D,E,F);
ctx.drawImage(img, sx,sy,sw,sh, 0,0,sw,sh);
```

**这是精确的，不是近似** —— 已用 Python 复现同一套公式并验证三个角点
（原点 / +u 端 / +v 端）的对应误差 < 1e-6。

### 坐标方向
DST 的 anim 数据里 **y 向下为正**（第四阶段用 ty 语义排序验证过），
与 canvas 一致，所以**不需要翻转 y**；UV 的 v 也直接对应图集 PNG 的上下。

## 3. ★★ 发现并修正了一个「静默缺件」的坑

做播放器时发现：**pigman 的 idle 帧有 21 个元素，只有 10 个被画出来**，
另外 11 个因为「符号在 build 里找不到」被静默跳过。

根因：**配套关系不能靠名字猜。**
```
pig_build.zip         ← 猪的贴图
ds_pig_basic.zip      ← 名字看着最像，其实是**单机版 Don't Starve** 的动画，
                        符号哈希与 DST 的 pig_build 对不上
```
我最初就是按名字配的 `pig_build + ds_pig_basic`，渲染出来的「猪人」
看着还挺像，其实是**缺了 11 个部件的残缺结果** —— 这类问题不会报错，
只会悄悄少画东西。

### 修正：按「元素命中率」自动配对
新增 `tools/find_anim_pair.py` 与 `tools/auto_export.py`：
对每个候选动画包，算它 **idle 类动画首帧的元素命中率**
（能在本 build 里找到对应符号的元素占比），取最高的几个合并。

**而且必须按动画逐个过滤**：合并多个包时，每个包都带着自己那套符号，
有些动画的元素在本 build 里根本找不到对应符号（会静默少画部件）。
实测 `pig_build` 合并 8 个包后，动画数从 9 涨到 95，
但元素覆盖反而从 80% 掉到 **41%** —— 因为多数新动画都对不上。
所以在 `export_anim.py` 里加了**逐动画命中率过滤**（默认阈值 85%），
宁可少而全，不要多而残。

### 最终配对与实测质量

| 生物 | 采用的动画包 | 符号 | 动画 | **元素命中率** |
|---|---|---|---:|---:|
| rabbit | `ds_rabbit_basic` | 16 | 30 | **99.7%** |
| spider | `ds_spider_caves` | 8 | 30 | **92.6%** |
| beefalo | `beefalo_actions` | 14 | 27 | **88.6%** |
| pig | `werepig_actions` 等 4 包 | 14 | 23 | 60.2% |

### ★ 一个如实标注的结论：`pig_build` 没有完全配套的动画包
把阈值提到 85% 时，**pig 的候选动画被全部丢弃（保留 0 个）**。
再查全库 3296 个 build：`ds_pig_basic` 只引用 12 个符号，
**没有任何单一 build 能覆盖超过 7 个**。

结论：DST 的 `data/anim` 里**不存在与 `pig_build` 完全配套的动画包**
（`ds_` 前缀的是单机版 Don't Starve 的，符号哈希体系不同）。
所以 pig 只能放宽阈值到 45% 才有动画可放 —— 渲染出来能看到猪头/耳/臂/腿/躯干，
但**缺裙、毛、脸颊等细节层**。这个缺口是**数据层面的，不是解析错误**。

## 4. 诚实说明

- 播放器的**渲染数学已验证**（仿射公式三处角点精确对应，
  `每 6 顶点 = 一四边形` 的结构也验证过）。
- 但**没能在真实浏览器里跑过**（本机没有可自动化的浏览器环境），
  只验证了内嵌数据结构与算法。首次打开若有问题，大概率在 UI 接线而非渲染。
- 跨包配对用的是「元素命中率」启发式：**不保证等于原版游戏的配对**，
  只是「能让这个 build 的动画画得最全」的组合。DST 里贴图与动画的
  权威对应关系可能存在别的配置文件里，没有去找。
