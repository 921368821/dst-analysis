## P1 · 验证覆盖：显式走到主循环不会走到的分支

> 这是第 21 节「静默空实现」的直接延续，也是**当前性价比最高的工作**。
> 理由：`DropDeathLoot` 那个 bug 证明「0 桩」不等于「没缺口」——
> 清单只覆盖会报错的缺口。而死亡/掉落这条路是**显式去走才发现**的。

### P1-1 燃烧链路（burnable）　✅ 已完成（新入口 `burn.lua`）

- **目标**：原版 `burnable` / `fire` 有完整的「点燃 → 蔓延 → 烧成焦炭 →
  掉落变熟食」链路（`lootdropper.lua:411` 的 burnt 分支会把 loot 换成
  `ash` / `<x>_cooked`）。
- **产出**：一段常驻验证，证明点燃一只生物后它真的烧完、掉落物真的被换成熟食。
- **前置依赖**：无（燃烧组件应该已随预制体加载；需先探明哪些全局缺失）。
- **风险**：可能暴露新的静默空实现——这正是目的。
- **✅ 结果**：完整链路跑通（Ignite → 1350 tick 烧完 → `burnt` 标签 →
  砍 → 掉 charcoal）。**并修掉两个缺失全局**：
  `GetSpecialCharacterPostProcess`（崩在协程里，静默）与
  `PrefabExists`（崩在链尾，东西已经掉出来了）。
  另记两处「我先想错、被实测纠正」：`burnt` 标签不是 burnable 加的；
  生物没有 `propagator` 所以烧不着（原版设定）。见报告第 25 节。

### P1-2 腐烂 / 潮湿 / 饥饿链路　✅ 已完成（`perish.lua`）

- **目标**：`perishable`（变质）、`moisture`（潮湿）、`hunger`（饥饿）
  都是「慢速推进 + 阈值触发」型组件，主循环 80 s 内未必走到阈值。
- **产出**：各自的阈值触发验证（如把 `perishable` 时间调短，确认真的变质并换 prefab）。
- **前置依赖**：无。
- **注意**：`GetIsWet` 恒 false 是已知宿主限制（已在 world.lua 输出中标注），
  所以潮湿只能验「组件自身推进」，不能验「被雨淋湿」。
- **✅ 结果**：`meat` 第 334 tick 换成 `spoiled_food`；hunger 150→0、
  第 31 tick `IsStarving()` 为真。附带对照发现：`burnt` 由预制体加、
  `spoiled` 由 `perishable.lua` 自己加 —— **标签归属有两种**。

### P1-3 拾取 / 容器 / 装备卸下　✅ 已完成（新入口 `equip.lua`）

- **目标**：目前只验了「装备 → 符号覆盖 → 画出来」。
  **卸下**（`ClearOverrideSymbol`）那条路没验——而它和戴上是对称的。
- **产出**：装备→卸下的完整往返验证，确认卸下后覆盖符号真的被清除。
- **前置依赖**：无（`ClearOverrideSymbol` 已在 `10_animstate.lua` 实现）。

## P2 · 渲染：接 GPU

> 唯一的大项。当前播放器是 canvas 2D 仿射四边形，
> 89 实体 + 15000 帧能跑，但离「实时」还有距离。

### P2-1 WebGL 渲染器　✅ 已完成（`tools/compare_renderers.py`）

- **目标**：把播放器的绘制后端从 canvas 2D 换成 WebGL，
  用实例化绘制（每个符号一个 quad），图集走纹理数组或图集 texture。
- **产出**：同一份轨迹数据在新后端下渲染，帧率对比（**必须多次采样**，
  见第 23 节——canvas 后端本身也可能有帧率波动）。
- **前置依赖**：
  - 现有的 `draw_sig` / 符号覆盖数据格式已稳定（✔ 已完成）
  - 图集 PNG 已嵌入播放器（✔ 已完成）
  - **注意**：需要保留 canvas 2D 作为对照与降级路径，否则无法证明「更快」
- **风险**：WebGL 在 headless 截图里可能不渲染（无 GPU），
  验证手段要从「截图」改为「readPixels 回读」或保留双后端 A/B。
- **✅ 结果**：后端早已实现，本轮补上 A/B 工具并证明 ——
  **scale=1 逐字节 100% 一致**（558000/558000），性能 **GL 快 3.58 倍**
  （5.660 → 1.583 ms/frame，软件光栅下测）。见报告第 26 节。

### P2-2 实时模式（可选）

- **目标**：现在播放的是**预烘焙轨迹**。实时模式要让 Lua 仿真在浏览器里跑。
- **产出**：需要 lua 编译到 JS（如 fengari 或 wasm 版 lua）——**这是独立大工程**。
- **前置依赖**：P2-1。
- **建议**：**先不做**。预烘焙轨迹已能完整展示「原版脚本不改一行运行」这个核心结论，
  实时模式的边际价值低于它的成本。
