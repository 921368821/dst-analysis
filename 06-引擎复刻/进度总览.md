### 4.2 三个「靠守恒而不是靠猜」的关键发现

**① KTEX 数据从 mip 表尾开始（分毫不差）**
```
abigail_attack_fx（128×128）:
  mip size 之和 = 16384+4096+1024+256+64+16+16+16 = 21872
  文件大小 21960 → 头 = 88 = 8（magic+标志）+ 8 项 × 10 字节 ✓
```

**② 符号条目定长 32 字节**
由「符号长度 = 8 + nframes × 32」在 41 个样本上成立
（`arm` 40B = 8+32，`inner wing` 72B = 8+2×32，`pinchers` 168B = 8+5×32）。

**③ 多图集的「符号 → 图集」归属（本轮最漂亮的一步）**
BILD 符号条目里**没有图集索引字段**（守恒是精确的），但有一条可推导的等式：
```
UV 跨度 × 图集尺寸 == bbox 的 w/h   →   图集宽 = bbox_w ÷ du
pig_head 177/0.08643 = 2048 (atlas-0)    pig_arm 86/0.08398 = 1024 (atlas-1)
```
每个符号**只有一个**图集能让等式成立。

## 九、方法论（这轮工作最可复用的部分）

全程只依赖两样东西：

1. **可证伪的守恒断言** —— 体积 / 数量必须对上。
   例：`mip size 之和 + 头长 == 文件大小`；`符号长度 == 8 + nframes×32`。
   靠它把候选假设一个个否掉，而不是靠肉眼猜字节。
2. **跨文件的语义交叉验证** —— 从 build.bin 解出的符号名，必须与从
   KTEX+DXT5 解出的像素内容语义吻合（`pig_head` 解出来得是猪头）。

另外几条省掉大量功夫的：

- **先搜官方文档再动手** —— Klei 的 `mod_tools/tools/scripts/buildanimation.py`
  注释里就有完整字段表，一步到位。
- **先让错误可读** —— UI 层那 8 个失败，补上原因摘要后一眼看出 4 个同因。
- **注意「本该同源」的表** —— `GROUND` 与 `WORLD_TILES`、`TUNING` 与 `constants`
  这类，单看都正常，只有交叉使用才暴露。
- **分母要选对** —— 批量统计时用错分母，会把 100% 算成 85%。
