# 恒值语义影响面（3.5）

> 对应计划条目：`后续计划单.md` **3.5「海洋 / 湿度 / 平台 / 真实光照」**。
> 该条的验收是二选一：**补实现**，或者**逐条写明「哪些 behaviour 因此永不触发」**。
> 本文件做的是后者 —— 但按本工程规矩，「写明」必须**有实测值支撑**，不能凭读代码下断言。

## 1. 为什么要单开一份文件

审计报告（P40）里写过一句：

> `IsInLight` 恒 false ⇒ `avoidlight` / `findlight` 两个 behaviour **永不触发**

本轮实测后发现这句话**一半是错的**：

| 说法 | 实测 | 结论 |
|---|---|---|
| `findlight` 永不触发 | 它**根本不调用** `IsInLight`（`behaviours/findlight.lua` 里 0 处），而是按 tag 找光源实体 | ❌ 说法错误 |
| `avoidlight` 永不触发 | 节点**会跑**（周期性翻转照常）；不成立的是「等待中被照到 ⇒ 立即切相位」这一条分支 | ⚠️ 降级为「部分失效」 |

⇒ 这正是本工程反复吃的亏：**「一句话扫一片」的断言，比没有断言更糟** ——
它让人以为查过了，于是没人再去查。所以这里把每个接口**逐个实测、逐个写后果**。

## 4. 逐条结论（人写的部分，机器不生成）

> **2026-10-18 更新（C1~C9 修复轮）**：本文件原来记的几条「恒值/永不触发」，
> 在 `06` 的**宿主侧**补了语义之后已经不成立了。`06` 仍然是「保真基线」——
> 补的不是「把原版行为改掉」，而是**把宿主里根本不存在的那个能力补上**，
> 让原版脚本走到它时能拿到一个真值。逐条改写如下，每条都给出**判据位置**
> （`mech.lua` 的第几段），因为「改好了」这件事必须有反向测试兜着。

### 4.1 平台判定：从「永不触发」变成**可达**（C4）

原来：`Physics:IsOnPlatform()` 返回 **nil**（三值逻辑里的「不知道」），
所有 `if inst.Physics:IsOnPlatform() then ... end` 恒走 else 分支。

更要紧的是**真正卡住 BOARDPLATFORM 的那一句**：
`dstsrc/scripts/actions.lua:445` 写的是

```lua
local function CheckIsOnPlatform(doer, dest)
    return doer:GetCurrentPlatform() ~= nil      -- ← 这个方法原来恒 nil
end
```

⇒ `BOARDPLATFORM`（上船）这条动作**永不可达**。而 `walkableplatformplayer.lua`
的 3 处调用是 `Transform:SetIsOnPlatform(true/false)` —— **只有 Setter，没有 Query**
是没法测的（设了也读不回来）。

现在：

| 位置 | 变化 |
|---|---|
| `Physics:IsOnPlatform()` | 返回 **bool**（`true/false`），不再是 nil |
| `Physics:SetIsOnPlatform(v)` | 新增，与 Query 成对 |
| `EntityScript:GetCurrentPlatform / SetCurrentPlatform` | 新增，成对，并同步 `Physics._onplatform` |
| `Transform:GetIsOnPlatform / SetIsOnPlatform` | 新增（`walkableplatformplayer` 用的就是 `Transform:SetIsOnPlatform`） |

判据：`mech.lua` **第 12 段（平台语义，6 条）**，含两条关键的反向断言 ——
「Query 返回的必须是 boolean，不是 nil」与「Setter 设 true 之后 Query 必须读回 true」。
把 `Physics:IsOnPlatform` 改回 `return nil`，这 4 条会红。

### 4.2 `avoidlight` 现在真的会「被照到就跑」（C3）

原来 `EntityScript:IsInLight()` 恒 **false** ⇒ 该 behaviour 的
「等待中被照到 ⇒ 立即切相位」这条分支**永不成立**，它只能按节拍翻转。

现在两处光照**读同一个源**：`TheWorld.state.phase`（`06` 的 `world.lua` 真挂了
`clock`，phase 会 day → dusk → night 推进），亮度取 day=1 / dusk=0.5 / night=0，
阈值 0.2 ⇒ **白天与黄昏 true、夜里 false**。

| 分支 | 现在 | 玩家能感知到的差别 |
|---|---|---|
| 周期性翻转 | ✔ 正常 | 无 |
| 「等待中被照到 ⇒ 立即切相位」 | ✔ **真的成立** | 举着火把靠近，它**会立刻跑** |
| 方向排序取「背光方向」 | ✘ 仍退化（`GetLightAngle()` 仍 nil） | 会躲，但躲的方向不是背光 |

★ 最后一行**没修**，且不在 C1~C9 里：补它需要一张**真实光照场**（按光源位置合成），
不是一个返回值能糊过去的。如实留着。

判据：`mech.lua` **第 13 段（光照语义，5 条）**，外加第 5 段「理智」改成**双向**判据
（夜里必须掉 **且** 白天必须不掉 —— 原来只判「给 0.3 跑 10 s 必须掉」，
而那条在宿主 `IsInLight` 恒 false 时也成立，等于用**假象**当基准）。

### 4.3 语义冲突已消除（C3）

原来同一个名字有两个相反的实现（`LightWatcher:IsInLight()` 恒 true /
`EntityScript:IsInLight()` 恒 false）。现在：

- `LightWatcher:IsInLight()` / `GetLightLevel()` / `GetLightValue()` 全部读 `ambient_light_level()`；
- `EntityScript:IsInLight()` 有 LightWatcher 就**委托**它，没有就退到 `Core.AmbientLightLevel()`；
- 新补 `EntityScript:IsInDark()`，与 `IsInLight()` **严格互补**（判据里锁了「不许同时为真」）。

★ 顺带修掉一个**会崩**的缺口：`components/sanity.lua:1282` 读
`LightWatcher:GetLightValue()`（宿主原来根本没有这个方法 ⇒ 泛化桩返回 nil ⇒
`nil > 0.6` 抛错）。现在它返回亮度。

### 4.4 诚实纠正：湿度不是缺口

审计里把「湿度恒值」算成缺口。实测：

- `TheWorld.state.humidity` = **nil**（字段不存在）✔ 真
- 但湿度能力在**组件**上：`components/moisture` + `inventoryitem:GetMoisture()`，
  `scripts/` 里 **78 处**调用，全部走组件路径，**不受影响**

⇒ 「世界的湿度」缺失是事实，但「湿度系统不存在」是**错的**。
这条从缺口表里撤掉。

### 4.5 边界坑：现在能判了（C5）

`Map:IsOceanAtPoint(x, y, z)` 实测：

| 点 | `IsOceanAtPoint` | `IsPassableAtPoint` | 解读 |
|---|---|---|---|
| (40, 40) 岛内 | false | true | 陆地 |
| (200, 200) 外海 | true | false | 海 |
| (500, 500) 越界 | **false** | false | **既非陆也非海** |

`IsOceanAtPoint` 对越界点仍返回 false（这是原版语义，不动）。但**「越界」这件事
从"猜"变成"可问"**了：

- 越界瓦片现在映射成 `GROUND.INVALID`（65535），不再是 `IMPASSABLE`（1）；
- 新增 `Map:IsOutOfBoundsAtPoint(x, y, z)`；
- `IsInvalidTile(tile)` = `IsImpassableTile(tile) or tile == WORLD_TILES.INVALID`
  （`tilegroups.lua:50` 的原义）⇒ 界外**不是一种地形**。

判据：`mech.lua` **第 11 段（地图边界语义，9 条）**。其中第 9 条是真正区分新旧实现的
那条 —— 「界外**不是**不可通行地形」（`IsImpassableTileAtPoint` 界外必须 false）：
第一版只断言「常量必须是 INVALID」，把实现退回 `IMPASSABLE` 时只红 1 条；
补了这条之后旧实现下红 2 条。

## 5. 没做的事（如实登记）

- **不补光照场**：需要「光源 → 光照图 → 每实体采样」，是渲染管线级别的工程（见 2.4）。
- **不补平台/船**：宿主没有海洋玩法，平台判定没有使用场景。
- **不改 `avoidlight`**：它是原版脚本，一行不改；宿主侧补光照才有意义。

⇒ 3.5 的处置是「**逐条写明后果**」这一支，不是「补实现」那一支。
