# Lua 版本迁移可行性（C7）

> 日期：2026-10-18 ｜ 对应：`校验报告-P43-2026-10-18.md` 的 C7
> 结论先行：**迁移可行，代价是一层 197 行垫片，原版 4030 个脚本一行都不用改。**
> 且这不是估算 —— 下面每个数字都是 `tools/lua_version_scan.py` 与
> `tools/lua54_trial.py` **跑出来的**，两条命令都能原地复跑。

## 1. 为什么这件事要单独结案

C7 的原文是：

> `weather` 组件在 Lua 5.1/LuaJIT 下编译不过（60 upvalue 硬上限）
> 影响：天气仍是桩
> 建议：换 5.2+ 运行时才解，改宿主解不了

「换 5.2+ 才解」是一句**结论**，但它自己从来没被验证过。要把它变成可执行的判断，
至少得回答三件事，而这三件事**一件都不能靠推理**：

1. 换过去之后，4030 个原版脚本还有几个编不过？
2. 编过 ≠ 能跑 —— 5.2+ 把 `loadstring` / `setfenv` / `unpack` 这些**全局函数删了**，
   它们是在执行期才炸的，编译期一个字都看不出来。
3. 天气组件到底**真的能用**了，还是只是"编过了、加载出来还是空表"？

## 2. 编译面（`tools/lua_version_scan.py`）

4072 个文件（`dstsrc/scripts` 4030 + 本工程 `host/` 25 + 根目录入口 17）× 5 个运行时，
逐个**只编译不执行**（编译期问题必须与运行期问题分开量）。

| 运行时 | `_VERSION` | 总数 | 通过 | 失败 | 其中 dstsrc | 其中 host+入口 |
|---|---|---|---|---|---|---|
| 5.1 | Lua 5.1 | 4072 | 4070 | 2 | 2 | **0** |
| 5.2 | Lua 5.2 | 4072 | 4071 | 1 | 1 | **0** |
| 5.3 | Lua 5.3 | 4072 | 4071 | 1 | 1 | **0** |
| 5.4 | Lua 5.4 | 4072 | 4071 | 1 | 1 | **0** |
| jit2.1 | Lua 5.1 | 4072 | 4070 | 2 | 2 | **0** |

失败明细只有两条，且性质完全不同：

| 文件 | 5.1 | 5.2+ | 性质 |
|---|---|---|---|
| `dstsrc/scripts/components/weather.lua` | ✘ `function at line 1622 has more than 60 upvalues` | ✔ **编过** | **这就是 C7 本身**：5.2+ 把 upvalue 上限从 60 提到 255 |
| `dstsrc/scripts/nis/xbnyn.lua` | ✘ `unexpected symbol near 'char(27)'` | ✘ 同样 | **与迁移无关**：文件里有一个裸 ESC 字节（`\27`），**每个版本都编不过**，5.1 也一样 |

⇒ 编译面的结论很干脆：**5.2+ 是严格更宽的**（少 1 个失败，不会多出来任何失败）。
本工程自己的 `host/` 与 14 个入口在**每个**版本下都是 0 失败。

## 3. API 面（同一工具，探针实测）

5.2+ 移走的全局函数（探针：`在` = 存在，`无` = 已移除）：

| 探针 | 5.1 | 5.2 | 5.3 | 5.4 | jit2.1 | 原版脚本里的用量 |
|---|---|---|---|---|---|---|
| `loadstring` | 在 | 无 | 无 | 无 | 在 | 27 处 |
| `setfenv` | 在 | 无 | 无 | 无 | 在 | 10 处 |
| `getfenv` | 在 | 无 | 无 | 无 | 在 | 10 处 |
| `unpack` | 在 | 无 | 无 | 无 | 在 | 559 处 `unpack(` |
| `table.getn` | 在 | 无 | 无 | 无 | 在 | 18 处 |
| `module` | 在 | 无 | 无 | 无 | 在 | 1 个文件 |
| `math.pow` | 在 | 在 | 无 | 无 | 在 | 34 处 |
| `math.atan2` | 在 | 在 | **无** | **无** | 在 | **213 处** |
| `bit32` | 无 | 在 | 无 | 无 | 无 | 0 处 |
| `goto` 是保留字 | 否 | **是** | 是 | 是 | 否 | 80 处 `goto`（全在注释/字符串里，不炸） |
| `//` 整除运算符 | 无 | 无 | 在 | 在 | 无 | — |
| 位运算符 `& \| ~` | 无 | 无 | 在 | 在 | 无 | — |

★ `math.atan2` 这一行是**跑出来才发现的**，也是整件事里最值钱的一条：
它不在任何"5.2 迁移清单"的显眼位置（它在 5.3 才删），但它一缺，
`prefabs/skilltree_wortox` 加载就抛错 → 宿主把错误吞掉换成**空表** →
上层 `BuildSkillsData(FN)` 变成 `attempt to call a table value`。

⇒ 报错位置离真因隔了三层。这也是为什么"运行面必须真的跑一遍"：
只扫 `loadstring/setfenv` 的清单会**漏掉它**，而它一个就能让 `mech.lua` 整段红。

## 4. 运行面（`tools/lua54_trial.py`）

给一层垫片 `host/compat52.lua`，把 14 个入口在 **5.1（基线）** 与
**5.4 + 垫片** 下各跑一遍。只统计"5.1 能过的入口"，否则既有缺口会污染迁移成本。

| 入口 | 5.1 | 5.4 + 垫片 |
|---|---|---|
| run / batch / player / play / full / render | PASS | PASS |
| seasons / equip / burn / perish | PASS | PASS |
| tests / mech / reachability / world | PASS | PASS |
| **合计** | **14 / 14** | **14 / 14** |

垫片覆盖的东西（`host/compat52.lua`，逐条都有"为什么"写在文件里）：

```
loadstring → load          setfenv / getfenv（用 _ENV upvalue 实现）
unpack → table.unpack      table.getn → #        table.maxn（重写）
math.pow → ^               math.atan2 → math.atan(y, x)
math.log10 / math.mod      math.cosh / sinh / tanh / ldexp / frexp
bit32（5.3+ 用原生位运算模拟）                     module（最小实现）
```

★ 一条硬纪律写在那个文件里：**能忠实补的才补，补不了的不许假装成功**。
`setfenv(1, env)`（数字形式）在 5.2+ 没有等价物 ⇒ 直接 `error`，而不是默默返回原函数。
「看起来设了环境其实没设」是最坏的一种兼容。

## 5. 天气组件到底能不能用（C7 的收益证据）

`weather.lua` 的 60 upvalue 上限是这次迁移的**唯一动机**，所以必须直接量它，
而不是用"14 个入口都过了"来代替（那 14 个入口并不 require weather）。

同一份探针（先 `Bootstrap.Setup()`，再编译 + 走宿主加载器）：

| 运行时 | 直接编译 | 加载出来的表 |
|---|---|---|
| 5.1 | ✘ `more than 60 upvalues` | **0 个键**（空表 = 桩） |
| 5.4 + 垫片 | ✔ | **5 个键**：`is_a / is_class / __index / is_instance / _ctor`（一个真类） |

⇒ C7 描述的症状（"天气仍是桩"）**在 5.2+ 下消失**：它从"编不过的空表"
变成了一个真正构造出来的组件类。

## 6. 结论与代价

| 问题 | 答案 | 证据 |
|---|---|---|
| 5.2+ 会让原版脚本更多编不过吗？ | **不会**，反而少 1 个 | 第 2 节表格 |
| 编过之后能跑吗？ | **能**，14/14 入口通过 | 第 4 节表格 |
| 代价是什么？ | **一层垫片**（197 行，`host/compat52.lua`）+ 运行时切换；**原版脚本零改动** | 第 3、4 节 |
| 天气组件修好了吗？ | 编译与加载都通了，从空表变成真类 | 第 5 节 |
| 还有别的坑吗？ | 有，且**已知**：`nis/xbnyn.lua` 的裸 ESC 字节（所有版本都坏，与迁移无关）；`goto` 在 5.2+ 是保留字（当前 80 处全在注释/字符串里，但**以后是新代码的风险点**） | 第 2、3 节 |

### 决策

**迁移的阻塞已经清零，可以迁，但不建议本轮就切。** 理由：

1. 宿主正式运行时仍是 5.1，`mech.lua` 的 50 条判据、三件套、`07` 的实时引擎
   全部按 5.1 校准过；切换运行时要连带重跑一遍全量校验，属于**独立的一轮工作**，
   塞进 C1~C9 这一轮会让两件事的结论互相污染。
2. 天气组件"能加载"≠"行为正确"：它现在是个真类，但它依赖的
   `TheWorld.state` 字段、`weather` 事件、客户端表现都还没验过。
   **把"编过了"读成"天气好了"正是 C2 里那句提醒的同型错误。**

⇒ 本轮交付的是**可执行的前提**（扫描器 + 垫片 + 14/14 的实测），
切换运行时这件事登记在 `后续任务清单.md`，条件写清了：
**什么时候决定迁，就什么时候跑那两条命令复核一遍，数字对得上才动手。**

## 7. 怎么复跑

```bash
cd 06-引擎复刻
. ../tools/env.sh

# ① 编译面 + API 面（约 13 秒，4072 文件 × 5 版本）
"$PY" tools/lua_version_scan.py --json _out/lua_version_scan.json

# ② 运行面（约 1.5 分钟，14 入口 × 2 运行时）
"$PY" tools/lua54_trial.py --json _out/lua54_trial.json

# ③ 单个入口手工对照
"$PY" "$RUNNER" 5.4 --prelude host/compat52.lua "$PWD/mech.lua"
```

⚠️ 这两个工具**刻意没接进** `tools/check_all.sh`：宿主的正式运行时还是 5.1，
把"迁移面"变成常驻红项只会训练人忽略红色。等真的切换运行时，再把它接进去
—— 那时它守的就是**当前**运行时，而不是一个假设。
