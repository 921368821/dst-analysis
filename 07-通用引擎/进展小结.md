## 1. 这是什么

引擎（Lua，原版宿主）的**实时化/可玩/可发布**分支。与 `06-引擎复刻`（保真基线，**不改一行**）分开：

## 3. 凭什么说它是好的（本工程的「母题」）

一句话：**任何「✔」都必须配一次「把它改坏、看它是否真的变红」**，否则不算数。

- **判据（15 组）**：Node 客户端验证 + 精灵渲染纯函数 + 二进制帧协议 + Python 端到端 +
  跨实现一致性 + 发布演练 + 静态检查 + **协议三列一致性** + **DrawCmd 逐顶点一致性** +
  规模并发 + 计划数字核对 + 宿主回归 + 06 三件套。
- **两条「跨实现守卫」**（P43）：`server.py ∪ client.html = protocol.md` 三列独立提取后必须相等；
  离线渲染器与实时渲染器**逐符号逐顶点**比 `xy`/`uv`/矩阵（4 build / 57 QUAD）。
  两条都先证明"会红"再报绿 —— 各带 6 / 7 条反向测试。
- **两份变异测试**（`①d` 客户端、`②f` 服务端/引擎）：把实现故意改坏，逐条确认**对应判据真的会红**；
  每条连续跑两遍（只红一次算抖，不算数）。
- **机械核对**：`tools/verify_plan.py` 把「计划里的可机器验证数字」和「README / 发布检查单里的数字」
  与实跑对照；`06` 侧还有 `audit_fixes` / `audit_doc_numbers` / `verify_report` 三件套。
- **本次长时任务新增的机械守卫**：客户端变异测试 13 条、服务端/引擎变异测试 13 条、
  静态未定义名检查、发布演练 7 条（含「停服先存后杀」「会话身份挺过真重启」）、
  文档数字核对（含「Lua 续行取模误用」规则）。

## 5. 最近一轮做了什么

**P43：给「两处实现应该一致」配上会红的判据**（§9ao）
- **协议三列守卫**（`tools/check_protocol.py`）：从 `server.py` / `client.html` / `protocol.md`
  三处**各自独立提取**命令集合，要求完全相等。真值取代码（`srv|cli`），**不取含文档的并集** ——
  否则 `--write` 会把文档里的假命令抄回文档，判据的输入里含被判定对象，永远过。
- **DrawCmd 逐顶点守卫**（`tools/check_drawcmd.js`）：离线（06 `render.lua` → `drawcmd.json`）
  与实时（07 `rt/render_atlas.js`）**逐符号逐顶点**比 `xy`/`uv`/矩阵。
  结果 4 build / 57 QUAD 全一致，最大差全是舍入量级（xy 4e-4 · uv 5e-5 · mat 1e-4）。
- ★ **两条守卫都在上线时抓到真缺陷，不是装门面的**：
  ① 守卫自己的正则 `[a-z_]+` **不含数字** ⇒ 含数字的命令三列全隐形（`sneak2` 谁都没看见）；
  ② `06/render.lua` 的挑动画判据 `as._nframe > 0` **恒真** —— 宿主对"动画不存在"会投影一条
     15 帧**合成动画**把 `_nframe` 填上 ⇒ rabbit/spider 拿到并不存在的 `idle_loop` ⇒
     `GetDrawList()` 空 ⇒ 导出 **0 个 QUAD** ⇒ 那条一致性判据在 4 个 build 上**2 个是空跑的**。
- **版本号补正**：`rt_boot.lua` 的 `M.version()` 一直是 `"rt_boot/5"`，而发布记录写的是 `/6`
  （P41/T6 换了 `act_targets` 实现，行为确实变了）。判据 B6 只核"两处是否一致"，
  **一起停在旧值时它是绿的** ⇒ 已补成 `6`。
