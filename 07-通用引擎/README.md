# 07-通用引擎 —— 把契约复刻引擎变成「能实时玩、能发布」的引擎

> **一句话**：让 `06-引擎复刻` 那套「跑原版 Lua」的宿主，**长出实时操作、实时画面、可发布**这三样能力。
> 它**不改原版脚本一行**，也不动 `06-引擎复刻` 的 14 入口基线。

---

## 30 秒上手

```bash
cd <工程根>/07-通用引擎   # 工程根 = 含 06-引擎复刻 / 07-通用引擎 的那一层；PY/NODE 由 tools/env.sh 解析

# ① 起服务端（自带端口守卫 + 健康检查 + 确认 tick 真的在走）
bash deploy/start.sh 8765 30
#   浏览器打开 http://127.0.0.1:8765/     ← WASD/方向键操控，**点目标选中要砍的那棵**，空格 砍/挖/捡
#                                        滚轮缩放，拖拽平移，F 跟随，P 暂停
#   📱 手机上打开同一个链接即可玩：左下**摇杆**移动、右下**动作**键、
#      单指拖拽平移、双指捏合缩放（`?pad=1` 可在桌面强制打开面板调试）
#   状态页      http://127.0.0.1:8765/status

# ② 跑全部验证（20 组 264 项 + 宿主 14 入口 + 06 三件套）
#   其中 ②d 是**发布演练**：走 deploy/start.sh → /healthz → WS 端到端 → stop.sh
bash tests/run_all.sh
#   结尾会打印完整日志路径 tests/_run_all.log（红了以后现场还在，不必靠重跑猜）
#   结尾还会打印**组数核对**：本次执行 N 组 / 脚本声明 N 组。
#     —— 为什么要有：文档里的「20 组」一直由 `verify_plan.py` 从**源码文本**数标签得到，
#        它管得住「文档写错」，管不住「某组被 `if false` 包住 / 被整段删掉」
#        （标签还在文本里，静态数照样 20，而那一组一次都没跑）。
#        现在这个数由 `hr()` **在真打印标题时** +1 ⇒ 只有真跑过才会涨。
#   改完 run_all 想先确认组数对不对，别等 11 分钟：
bash tests/run_all.sh --dry-run        # 只走组标题、不执行判据（约 1 分钟，结论不作数）
bash tests/run_all.sh --fast-dry       # 同上，走 --fast 分支（约 5 秒）
```

停服：`bash deploy/stop.sh 8765`（**按端口找 PID**，不靠记 PID）。

### 录像 / 回放（M7）

```bash
# 录：种子 + 输入事件 + 每 tick 指纹（每 30 s 原子落盘一次）
python rt/server.py --record deploy/logs/run.json
# 放：换台机器/换了代码，用同一份录像**逐 tick** 对指纹
python rt/server.py --replay deploy/logs/run.json --seed 20261015
#   一致 → 退出码 0；不一致 → 1（并报出第几个 tick 起分叉）；拒绝回放 → 2
```

判据是**逐 tick 指纹全同**，不是「看着差不多」—— 所以它能当**回归测试**用：
改了引擎之后放一遍老录像，立刻知道行为有没有变。反向判据在
`tests/test_rt.py` 的 `B19`（人为改一个字节必须被抓到**并定位到 tick**）。

## 三条设计原则（都是踩出来的）

1. **不改原版、不动基线** —— `06-引擎复刻` 的 14 入口是「保真度」的度量，任何新能力都长在 `07` 侧。
2. **失败要吵，不许静默** —— 所以有：端口占用守卫、物理积分错误计数、坏帧计数、
   自满足特征串检查、`start.sh` 里「tick 真的在增长」的二次确认。
   （今天所有难查的问题，根因都是「某个地方把错误吞了」。）
3. **判据要么守住承诺，要么如实报告** —— 不拿「探索出来的上限」当红线（那只会制造假报警，
   而假报警会训练人忽略工具）；历史数字按工程约定标「**当时值**」，不删。

## 不做（产品决策，不是遗漏）

> 「不做」和「没做」是两件事。这里每条都写**为什么不**，以及**要做得先付什么**。
> 列出来的目的：下一个人（或未来的我）不会把它当待办重新捡起来，也不会
> 因为「测试里没有」而误以为漏了。

| 不做的事 | 为什么不 | 真要做的前置条件 |
|---|---|---|
| **完整编辑器**（撤销/重做、多选、复制粘贴、变换手柄、Prefab 编辑模式） | P62 只做「看 → 选 → 改 → 存」这条闭环，且**已配判据守着**。加这些东西之前先得回答「编辑器是给谁用的」——自己调世界，还是给别人做 Mod | 先有 Mod 加载器；或明确要对外开放场景编辑 |
| **Mod 支持**（`mods/`、`modmain.lua`、`AddModPrefab`） | 本引擎的定位是「跑原版脚本 + 学结构」，不是做 mod 平台。mod 加载器要复刻原版的 sandbox / 加载顺序 / 冲突覆盖规则，工作量与收益不成比例 | 先有一个真的要用 mod 的场景 |
| **原版 UI（widget / screen 体系）** | 原版 UI 依赖 `TheFrontEnd` + 动画 + 输入焦点三层，且**与玩法无关**。客户端已经自写了一套够用的 HUD | 决定「要原版观感」而不是「能玩」时 |
| **实体间碰撞（生物互相推挤）** | 原版靠引擎物理体；宿主只有瓦片级碰撞（见 `代理语义总览.md` 第 7 行）。做实体间碰撞要引入 broadphase + 求解器，且会改变现已验证的移动手感 | 需要「挤在一起」的玩法时（如围栏赶牛） |
| **RPC（`SendRPCToServer` 等）** | 客户端与服务端之间已经有 WS 消息通道；再复刻一套 RPC 等于两条通路做同一件事 | 有原版 prefab 非 RPC 不可时（目前没有） |
| **音频后端（FMOD）** | 版权 + 平台依赖。当前只产出**结构化声音事件**（可校验、可回放），没有声音输出 | 换自产音源 + 允许平台相关依赖 |
| **完整 WebGL 渲染管线** | 现有 Canvas 2D + 图集精灵已经能表达原版动画的全部信息（`drawcmd` 逐顶点校验过）。上 WebGL 只有在实体数/特效量真的顶不住时才有意义 | 实测帧率成为瓶颈时（当前 640 实体 30 Hz 占 75% 预算） |
| **多人联机的原版网络模型**（`shard` / `netid` 同步） | 本引擎是**权威服务端 + 单房间**模型，已经能多客户端（4 个客户端 = 4 个角色）。跨房间/跨服要重做世界一致性 | 需要真·专用服务器分片时 |

## 已知限制（不藏）

- **编辑器只对「本机」开放**（P62）：`/editor/*` 的门槛是**请求来自回环**
  （`127.0.0.1` / `::1` / `::ffff:127.0.0.1` / `localhost`），不看 `--allow-debug`。
  ⇒ 从别的机器打开这个页面时，编辑器面板能显示但每个操作都返回 **403**。这是设计如此：
  编辑器能删对象、挪玩家、刷物品，不该跟「运维通道」共用一个开关。
  真要远程编辑，走 SSH 端口转发把 8765 映射到本机，而不是把门槛拆掉。
- **左侧那片黑不是渲染 bug**：世界是 128×128 的**圆形岛**，玩家在岛边时，
  屏幕一侧对应的是**世界之外的负坐标**，那里没有地形 ⇒ 露出画布底色。
  `地形=128×128` 与 `缩放` 两个数字能当场印证。按 F1 打开编辑器、点列表里的对象「聚焦」，
  相机就会回到有内容的地方。

- **战斗是单向的**（P61）：玩家能打生物 —— 点它、走过去、打、掉血、死、掉战利品（可捡）。
  但**生物不会反击**：实测 spider 被连打 10 下（100→0 血）全程不还手，玩家血量 150 一点没掉。
  攻击链路本身通（`GetAttacked` ← `DoAttack`），缺的是 brain 的**仇恨/反击**那一层。
  ⇒ 现在是「玩家单方面清场」，不是对等战斗。
- **攻击没有动画**：导出的 wilson build 里根本没有 `attack` 符号（`rt_boot.lua:439` 有取证），
  所以是「原地出手」——**伤害与掉落是真的，动作不是**。
- **发布版不带原版美术**（版权）⇒ 默认用 `_demo_atlas/` 的自产素材；想要更好美术，重跑 `pack_atlas.py`。
- **公网部署需要一台能跑 `Python 3.13 + lupa` 的机器**；纯静态托管跑不了服务端。
- **昼夜明暗是客户端「看起来像」的近似**：服务端只发**相位**三档（day/dusk/night），
  不带原版那条连续环境光曲线（`components/ambientlighting.lua` 仍没被送出来）；
  暗度是客户端按相位平滑追赶的（`client.html` 的 `DARK_TARGET`）。
  要还原原版光曲线，得把 ambientlighting 的逐分钟值也加进帧里。
  ⚠️ 世界**规则**（昼夜/季节/温度）是**真原版组件**在跑，这一条只影响「画面亮度」。
- **原版 `wander.lua` 有一个角度单位笔误**（`WalkInDirection(angle/DEGREES)` 传了弧度，
  而该参数要的是度）⇒ 漫游中的生物朝向会有一处**确定性的偏差**。**本工程不改原版一行**，
  所以只记录、不修（完整取证见 `开发计划.md` §9n.3）。
- **地形是「真瓦片 + 自配调色板」**：瓦片 id 来自引擎里那张真表（与原版 tilegroups 同源），
  但**颜色是客户端写死的一张表**（`client.html` 的 `TILE_COLOR`），不是原版地面美术。
  想换观感改那张表即可；要还原原版地面得走 `pack_atlas.py` 那条路自产图集。
- 640 实体档占 30 Hz 预算 **75%**，余量不大（默认世界只有 6 实体，余量 500×）。
- **增量帧没做**：实测每帧变化率 55%，收益抵不上「增删跟踪 + 关键帧重同步」的复杂度
  （判据写在 `tests/test_stress.py` 的 `S4`，改主意前先看那个数）。
- **交互的能力（2026-10-16 更新）**：**找目标 / 走过去 / 砍倒（树会倒、会掉 `log`）/
  捡起地上的物品** —— 都跑通了（判据 `E1`/`E2`/`E3`），三种拒绝也**说得出原因**。
  ⚠️ 旧版这里写的「砍倒与掉落没跑通」「拾取不可用」**两条诊断都是错的**：
  前者是**玩家中途死了**（见下一条），后者是**拿一个原版根本没有的方法当基准**
  （原版没有 `GetItems`；真实接口 `GetItemInSlot`/`FindItem`/`Has`/`GiveItem` 在宿主里都能用）。
  更正明细见 `开发计划.md` §9y。
- **✅ 夜里站在火边就能活（2026-10-16 修）**：宿主**没有逐点光照** ⇒ 引擎里那条
  「站在光里就不挨打」只能**代理**：07 用「**离点着的营火足够近**（默认 7 格）」+ 昼夜相位判断，
  并会在**黄昏时自动在你附近点一堆营火**（原版要玩家自己造火）。
  实测一个周期 `day 250 s / dusk 180 s / night 60 s`：站在火边**整夜满血**（判据 `E7`）；
  **走远照样会被黑暗打死**（这一点忠于原版）。
  ⚠️ 代理的极限：火把 / 矿灯 / 发光生物这些光源**不算数**（只认登记过的营火）；
  火会烧完（约 140 s），所以每到一个黄昏会补一堆。见 §9ae。
- **✅ 死亡 ⇒ 3 秒后自动复活（2026-10-16 已修）**：以前玩家死后状态机停在 `death`
  （`SGwilson` 的 death 状态**出不去**），`act` 仍返回成功但什么都不发生 ⇒ **世界永久停摆**。
  现在 `rt_boot` 会在死满 3 秒后**换一具身体**（原版是变 ghost，本宿主没有 `SGghost`），
  客户端每 2 s 例行重问 `whoami`、发现 guid 变了就自愈采纳。
  ⚠️ 这是 07 侧的**行为选择**（原版要跑回复活台），`respawns` 计数在 `/healthz` 上可见。
- **已知未解**：某种客户端节奏（连上后立刻高频发消息 + 紧循环读帧）会让服务端的
  模拟循环停住（`tick` 几乎不涨）；真实客户端的节奏（持续读 + 定时发）不受影响。
  已二分到「回 `targets` 应答」这一步，但**根因未定** —— 复现条件与已排除项见 §9v.5。
